# META-01. Повторяющийся uuid у объектов метаданных

## Идентификатор и группа

Идентификатор: `META-01`
Группа: `META` (метаданные)

## Важность

Major

## Триггер

У двух объектов метаданных в исходниках один и тот же uuid

## Почему дефект

uuid идентифицирует объект при обмене, сравнении и объединении конфигураций: совпадение делает объекты неразличимыми. Выгрузка и загрузка затирают один объект другим, ссылки из расширений вяжутся не к тому объекту; платформа принимает такие исходники без диагностики.

## Законная форма

У каждого объекта метаданных свой uuid; новые объекты получают его платформой при создании.

```xml
<mdObject class="Catalog" uuid="a1b2c3d4-e5f6-7890-a1b2-c3d4e5f67890">
    <name>Склады</name>
</mdObject>
<mdObject class="Catalog" uuid="09f8e7d6-c5b4-a392-8172-6f5e4d3c2b1a">
    <name>Магазины</name>
</mdObject>
```

## Как чинить

Сгенерируй новому объекту собственный uuid (при создании объекта платформой или редактором метаданных) и обнови все ссылки на старое значение. Перед выгрузкой проверяй уникальность uuid поиском по значению в дереве исходников: платформа дубликат не диагностирует.

## Детекторы

| Среда | Детектор | Уровень |
|-------|----------|---------|
| EDT | чтение | read |
| Конфигуратор | чтение | read |

Обоснование чтения: Повтор uuid виден только сравнением двух и более объектов метаданных; инструменты словаря проверяют один объект, кросс-объектовой свертки нет.

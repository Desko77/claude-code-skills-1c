# MODEL-18. Молчаливая обработка исключения

## Идентификатор и группа

Идентификатор: `MODEL-18`
Группа: `MODEL` (признаки кода, написанного моделью)

## Важность

Major

## Триггер

Блок Исключение пуст или завершается без записи в журнал регистрации и без повторного вызова исключения

## Почему дефект

Ошибка проглатывается без следа: сбой не виден ни пользователю, ни администратору, диагностика невозможна. Код после Попытки продолжает работу с данными в неопределенном состоянии: частично обработанные записи читаются как успешные. Пустой блок Исключение - самый частый вид этого дефекта.

## Законная форма

Исключение обработано осознанно: ожидаемая и проверенная ситуация (отсутствие файла, отказ внешнего сервиса) с записью в журнал или комментарием причины; восстанавливающая операция в транзакционном коде по схеме TXN-04/TXN-05.

```bsl
Попытка
    Данные = ПрочитатьФайлОбмена(ИмяФайла);
Исключение
    ЗаписьЖурналаРегистрации("Обмен.Чтение", УровеньЖурналаРегистрации.Ошибка,,,
        ОписаниеОшибки());
    ВызватьИсключение ОписаниеОшибки();
КонецПопытки
```

## Как чинить

Запиши ошибку в журнал регистрации с уровнем и комментарием, достаточным для диагностики, и либо обработай ситуацию по смыслу, либо вызови исключение повторно. Для диалоговых ожидаемых ситуаций достаточно сообщения пользователю без повторного вызова.

## Детекторы

| Среда | Детектор | Уровень |
|-------|----------|---------|
| EDT | ask_1c_ai | llm |
| EDT | чтение | read |
| Конфигуратор | bsl_validate:MODEL-18 | static |

Обоснование чтения: lint-правило ловит пустой блок Исключение; блоки с кодом без журнала и без повторного вызова требуют оценки осознанности обработки.

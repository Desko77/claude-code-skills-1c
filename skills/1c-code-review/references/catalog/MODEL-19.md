# MODEL-19. Регламентное задание без идемпотентности

## Идентификатор и группа

Идентификатор: `MODEL-19`
Группа: `MODEL` (признаки кода, написанного моделью)

## Важность

Major

## Триггер

Тело регламентного задания выполняет записи без защиты от повторного запуска: документы и движения создаются заново при каждом выполнении, нет отбора необработанных данных и проверки уже созданных записей

## Почему дефект

Повторный запуск повторяет побочные эффекты: дубли документов, задвоенные движения и начисления. Причины повтора штатны - перезапуск после сбоя, ручной запуск из консоли параллельно расписанию, повтор после таймаута - поэтому задание обязано приводить базу к одному и тому же состоянию, а не добавлять эффекты поверх.

## Законная форма

Задание читает только необработанные данные: отбор по признаку обработки или периоду после последнего успешного выполнения; создание записи через поиск существующего. Проверка и создание выполняются под управляемой блокировкой по ключу периода внутри транзакции: параллельный запуск ждет блокировку и видит записи, созданные первым.

```bsl
Процедура НачислитьПени()
    ПоследняяДата = Константы.ДатаНачисленияПени.Получить();
    НачатьТранзакцию();
    Попытка
        Блокировка = Новый БлокировкаДанных;
        ЭлементБлокировки = Блокировка.Добавить("РегистрСведений.НачисленныеПени");
        ЭлементБлокировки.УстановитьЗначение("Период", НачалоМесяца(ПоследняяДата));
        Блокировка.Заблокировать();
        Для Каждого Долг Из ДолгиПосле(ПоследняяДата) Цикл
            Если ПениУжеНачислены(Долг.Договор, ПоследняяДата) Тогда
                Продолжить;
            КонецЕсли;
            СоздатьНачислениеПени(Долг);
        КонецЦикла;
        Константы.ДатаНачисленияПени.Установить(ТекущаяДатаСеанса());
        ЗафиксироватьТранзакцию();
    Исключение
        ОтменитьТранзакцию();
        ВызватьИсключение;
    КонецПопытки
КонецПроцедуры
```

## Как чинить

Ограничь выборку необработанными данными: признак обработки, период после контрольной даты, хранимая отметка прогресса. Перед созданием записи проверяй существование результата прошлых запусков; проверку и создание закрывай управляемой блокировкой по ключу периода внутри транзакции - иначе два параллельных запуска пройдут проверку одновременно и создадут дубль. В начале процедуры добавь стандартный вход БСП: ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания.

## Детекторы

| Среда | Детектор | Уровень |
|-------|----------|---------|
| EDT | ask_1c_ai | llm |
| EDT | чтение | read |
| Конфигуратор | чтение | read |

Обоснование чтения: идемпотентность - свойство поведения, а не текста: текстовый детектор не отличит фильтр необработанных данных от фильтра по параметру; требуется чтение запроса отбора.

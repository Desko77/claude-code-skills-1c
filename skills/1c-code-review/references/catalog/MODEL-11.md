# MODEL-11. Проверка наличия собственного реквизита по метаданным

## Идентификатор и группа

Идентификатор: `MODEL-11`
Группа: `MODEL` (признаки кода, написанного моделью)

## Важность

Minor

## Триггер

Обращение к реквизиту собственной конфигурации обложено проверкой его наличия через метаданные

## Почему дефект

Реквизит собственной конфигурации есть всегда: ветка "реквизита нет" недостижима, код содержит ложную неуверенность в собственной схеме. Проверки по метаданным засоряют метод и скрывают настоящее условие.

## Законная форма

Проверка по метаданным нужна для данных, которые реально могут отсутствовать: объект из другой конфигурации, расширение на нескольких базах.

```bsl
Реквизиты = Метаданные.Справочники.Контрагенты.Реквизиты;
Если Реквизиты.Найти("СрокОплатыХозяина") <> Неопределено Тогда
    Срок = Контрагент.СрокОплатыХозяина;
КонецЕсли;
```

## Как чинить

Убери проверку наличия у реквизитов, объявленных в этой же конфигурации, и обращайся к ним напрямую. Проверку по метаданным оставь только для объектов и реквизитов, состав которых меняется между базами или версиями.

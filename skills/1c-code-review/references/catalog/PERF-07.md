# PERF-07. Временный файл не удален

## Идентификатор и группа

Идентификатор: `PERF-07`
Группа: `PERF` (производительность)

## Важность

Major

## Триггер

Код получает имя временного файла или строит свой путь в каталоге временных файлов, пишет туда и завершает работу без удаления

## Почему дефект

Временные файлы накапливаются и занимают место на диске сервера. Собственный путь в каталоге временных файлов платформа не отслеживает: такой файл не удаляется никем, каталог растет до исчерпания места, обслуживание без простоев невозможно. Имя, полученное ПолучитьИмяВременногоФайла, платформа отслеживает и удаляет сама: в клиент-серверном варианте - в течение 20 минут после завершения сеанса или серверного вызова, в файловом - при следующем запуске платформы. Дефект для такого файла мягче: до автоудаления он удерживает место и данные, поэтому явное УдалитьФайлы() после использования остается рекомендацией.

## Законная форма

Файл удаляется сразу после использования, в том числе при ошибке обработки; для имени из ПолучитьИмяВременногоФайла допустимо положиться на автоудаление платформой, когда удержание файла до таймера очистки приемлемо.

```bsl
ИмяФайла = ПолучитьИмяВременногоФайла("xml");
Попытка
    Данные.Записать(ИмяФайла);
    ПрочитатьДанные(ИмяФайла);
Исключение
    УдалитьФайлы(ИмяФайла);
    ВызватьИсключение ОписаниеОшибки();
КонецПопытки
УдалитьФайлы(ИмяФайла);
```

## Как чинить

Обработку файла оберни так, чтобы удаление выполнялось и при ошибке: выделенный блок с удалением после использования или отдельный метод очистки в исключении. Для промежуточных данных предпочитай ПолучитьИмяВременногоФайла и хранилище значений вместо собственного пути в каталоге временных файлов: имя из ПолучитьИмяВременногоФайла платформа чистит по таймеру, собственный путь не чистится никогда.

# CLIENT-05. Синхронный вызов, недоступный в веб-клиенте

## Идентификатор и группа

Идентификатор: `CLIENT-05`
Группа: `CLIENT` (клиент-серверное взаимодействие)

## Важность

Major

## Триггер

В клиентском коде вызван синхронный или модальный метод: Вопрос, Предупреждение, ОткрытьЗначение, семейство Ввести, синхронные методы HTTPСоединения - либо оператор Перейти в клиентском модуле

## Почему дефект

В управляемом приложении с запрещенной модальностью синхронный вызов завершается ошибкой выполнения: свойство конфигурации Режим использования модальности со значением Не использовать (значения свойства: Использовать, Использовать с предупреждениями, Не использовать; состав значений сверен по свойствам конфигурации) не дает выполнить такой код. В веб-клиенте синхронные вызовы не поддерживаются платформой: форма падает при первом обращении. Оператор Перейти в клиентском коде форм и команд не работает в веб-клиенте.

## Законная форма

Серверный код без интерфейсных вызовов; вызов асинхронного аналога с обработчиком оповещения.

```bsl
&НаКлиенте
Процедура УдалитьФайл(Команда)
    ПоказатьВопрос(Новый ОписаниеОповещения("ПослеУдаления", ЭтотОбъект),
        "Удалить файл?", РежимДиалогаВопрос.ДаНет);
КонецПроцедуры
```

## Как чинить

Замени синхронный вызов асинхронной парой: Вопрос - ПоказатьВопрос, Предупреждение - ПоказатьПредупреждение, Ввести - ПоказатьВвод, ОткрытьЗначение - ПоказатьЗначение; продолжение логики перенеси в обработчик оповещения. Синхронные методы HTTPСоединения замени на асинхронные методы с суффиксом Асинх. Перейти в клиентском коде замени на рефакторинг условия.

| Среда | Детектор | Уровень |

Обоснование чтения: доступность вызова зависит от режима модальности конфигурации и контекста компиляции; lint-правило ловит перечень имен, решение о дефекте требует чтения.

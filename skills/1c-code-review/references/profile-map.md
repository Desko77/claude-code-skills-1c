# Профиль правки

Спецификация профиля: по каноническому множеству изменений (`changeset.md`) профиль
определяет класс объема, архетипы, среду и обязательный состав проверок. Реализация -
`tools/change_profile.py` (функция `compute_profile`); валидатор следа `tools/evidence.py`
сверяет события прогона с обязательным составом из события `scope`. Идентификаторы
проверок фиксированы таблицей ниже, новые не вводятся.

## Классы объема

Объем считается по файлам канонического множества:

- файл кода - файл множества с суффиксом `.bsl` или `.os`;
- файл метаданных - файл множества, подходящий под правило распознавания метаданных
  (таблица архетипов, строка "изменение метаданных");
- измененные строки файла - сумма добавленных и удаленных строк по
  `git diff --numstat` относительно base. Файл множества со статусом `modified` либо
  `added`, у которого numstat дает удаление (арбитраж `git rm --cached` при измененном
  рабочем файле: текст diff - `+++ /dev/null`) либо записи нет (неотслеживаемый),
  считается целиком: все строки рабочего файла добавленные. Удаленный файл дает записи
  numstat и отдельно не пересчитывается.

| Класс | Условие |
|---|---|
| C0 | нет ни файлов кода, ни файлов метаданных (только документация и прочее) |
| C1 | есть код: измененных строк BSL не больше 30, файлов кода не больше 2, файлов метаданных нет |
| C2 | не C1 и измененных строк BSL не больше 300; любая правка метаданных без новых объектов тоже C2 |
| C3 | измененных строк BSL больше 300, либо в множестве есть новый объект метаданных - добавленный (`added`) файл метаданных |

Пороги включающие: 30 строк и 2 файла - еще C1, 300 строк - еще C2.

## Архетипы

Архетип распознается по путям множества и тексту diff. Текст - добавленные строки и
контекст (`git diff -U3`, 3 строки вокруг правки) относительно base; файл со статусом
`modified` либо `added`, у которого numstat дает удаление либо записи нет
(неотслеживаемый, арбитраж `git rm --cached`), сканируется по рабочему файлу целиком.
Поиск подстрок с учетом регистра: написания в таблице устойчивы. Правка попадает в
несколько архетипов одновременно.

| Архетип | Признак по пути | Признак по тексту |
|---|---|---|
| транзакция | - | `НачатьТранзакцию` |
| блокировка | - | `БлокировкаДанных`, `Заблокировать` |
| права | `Rights.xml`, `.rights`, сегмент `Roles` | `УстановитьПривилегированныйРежим`, `ПравоДоступа` |
| запрос | `.dcs` | `Новый Запрос`, `ВЫБРАТЬ` |
| модуль формы | сегмент `Forms` с именем `Module.bsl`, `Form.form`, `Ext/Form/Module.bsl` | - |
| событие объекта | - | `ОбработкаПроведения`, `ПередЗаписью`, `ПриЗаписи`, `ОбработкаУдаленияПроведения` |
| новый общий модуль | `added` и сегмент `CommonModules` | - |
| перехват в расширении | - | `&Вместо`, `&Перед`, `&После`, `&ИзменениеИКонтроль` |
| изменение метаданных | `.mdo`, `.form`, `.dcs`, `Rights.xml`, `.rights`, сегмент `Roles`, `.xml` при `Configuration.xml` в корне репозитория (признак выгрузки Конфигуратора, `edt-source-format.md`) | - |
| любой BSL | `.bsl`, `.os` | - |

Текст сканируется у файлов кода; файлы метаданных задают архетипы только путем.
Сегмент - элемент пути между разделителями (`src/CommonModules/X/Module.bsl` содержит
сегмент `CommonModules`).

## Среда

Среда определяется по файлам кода и метаданных; файлы документации среду не задают.
Файл принадлежит среде `edt`, если у него есть каталог-предок с файлом `.project`,
содержащим строку `com._1c.g5.v8.dt` (признак проекта 1C:EDT); иначе `configurator`.
Профиль перечисляет все встреченные среды: правка одновременно в дереве EDT и в выгрузке
Конфигуратора дает обе, и обязательные проверки обеих сред складываются.

## Обязательные проверки

Идентификатор проверки в `required` пишется как `<проверка>@<среда>`; среда `any` -
проверка не зависит от среды. Состав складывается из всех сработавших строк:

| Условие | Среда | Проверки |
|---|---|---|
| архетип любой BSL | edt | `code_review`, `ask_1c_ai` |
| архетип любой BSL | configurator | `syntaxcheck`, `bsl_validate` |
| архетип запрос | edt | `validate_query` |
| архетип запрос | configurator | `query_validate` |
| архетип изменение метаданных | edt | `validate_for_export`, `get_project_errors` |
| архетип изменение метаданных | configurator | `meta_validate` |
| архетип права | edt | `security_audit` |
| архетип права | configurator | `role_validate` |
| архетипы транзакция, блокировка, событие объекта | любая | `catalog_read:TXN` |
| архетип перехват в расширении | любая | `catalog_read:EXT` |
| архетип перехват в расширении | edt | `validate_for_export` |
| архетип модуль формы | любая | `catalog_read:CLIENT`, `catalog_read:FORM` |
| класс C2 и выше | любая | `cross_review` |
| класс C3 | любая | `adversarial_audit` |

`catalog_read:<ГРУППА>` - проход по карточкам группы каталога чтением (`INDEX.md`).
Состав обязательных проверок пересчитывается после окончательного класса: понижение
класса убирает `cross_review` и `adversarial_audit`.

## driver

driver - что подняло класс. Порядок решения: первое сработавшее условие задает класс
и driver.

| Условие | Класс | driver |
|---|---|---|
| нет файлов кода и метаданных | C0 | `нет файлов кода и метаданных` |
| добавленный файл метаданных | C3 | `архетип: новый объект метаданных: <путь>` |
| строк BSL больше 300 | C3 | `объем: N строк BSL` |
| есть файлы метаданных | C2 | `архетип: изменение метаданных` |
| строк BSL больше 30 | C2 | `объем: N строк BSL` |
| файлов кода больше 2 | C2 | `объем: N файлов BSL` |
| прочий код | C1 | `объем: N строк BSL в M файлах` |

## Калька типового

Довод `--vendor-copy "<обоснование>"` понижает класс C2 или C3 до C1 (C0 остается C0),
driver становится `явное указание: калька типового`, обоснование пишется в событие
`scope` полем `vendorCopy`. Условия переноса типового кода (`rules/bsl-ssl.md`, разметка
правок типовых модулей):

1. правка - перенос типового кода (модуль БСП или внешней библиотеки, обновляемой
   извне), обернут маркерами `// <<МОДИФИКАЦИЯ` и `// >>`; однострочная правка -
   хвостовым маркером;
2. замененные или удаленные строки типового кода сохранены закомментированными внутри
   блока маркеров;
3. маркеры не содержат номеров задач, дат и авторов: это merge-метаданные, не журнал.

Условия подтверждает вызывающий; инструмент проверяет наличие довода и переносит
обоснование в след.

## analyzerConfig

Уровень конфигурации анализатора: `project-config` - гейтовый конфиг bsl-language-server
не отделен от проектного (довод `configurationPath` у `code_review` еще не вышел). Пишется
в событие `scope` полем `analyzerConfig`.

## CLI

```
python tools/change_profile.py --repo <каталог> --base <коммит> [--session <id>]
    [--vendor-copy "<обоснование>"] [--json] [--no-write]
```

- без `--json` печатает таблицу для человека: класс, driver, архетипы, среды,
  обязательные проверки;
- `--session` - пишет событие `scope` в каталог следа (`evidence-format.md`); без него
  событие не пишется, `--no-write` подавляет запись при заданной сессии;
- каталог следа лежит вне репозитория, запись события каноническое множество не меняет;

Коды выхода: 0 расчет выполнен, 2 отказ (каталог не найден, не репозиторий, git
недоступен, base не разрешается, недопустимый идентификатор сессии).

Экспортируемая функция: `compute_profile(repo_dir, base="HEAD", vendor_copy=None) -> dict`.
Возвращает поля профиля с `base` и `diffHash`: `volume` (class, bslLines, bslFiles),
`files`, `archetypes`, `env`, `driver`, `required`, `analyzerConfig`, `vendorCopy`.

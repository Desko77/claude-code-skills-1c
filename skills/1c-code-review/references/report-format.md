# Формат отчета ревью

## Ключ находки

Каждая находка идентифицируется ключом:

```
<путь>::<Метод>:<строка>
```

- `<путь>` - путь к модулю от корня проекта;
- `<Метод>` - имя процедуры или функции, в которой строка;
- `<строка>` - номер строки первой строки находки.

Одна локация - одна находка. Одна и та же строка не порождает двух записей, даже если
подходит под две карточки: выбирается карточка с большей важностью, вторая упоминается в
пояснении. Несколько локаций одного дефекта (например, один и тот же запрос в трех циклах) -
отдельная запись на каждую локацию.

## Структура отчета

```
# Ревью: <задача или область>

## Вердикт

чисто | с находками | с пробелами

Critical: N, Major: N, Minor: N (из них долг: N)

## Находки

### [<важность>] <ИДЕНТИФИКАТОР> <ключ находки>
  Триггер: что видно в коде
  Почему дефект: последствия
  Как чинить: способ исправления

## Проверено

- <проверка> - чем подтверждена (инструмент, прогон, чтение карточки)

## Не проверено

- <проверка> - почему не выполнена
```

## Вердикт

- "чисто" - обязательные проверки выполнены, находок нет;
- "с находками" - есть находки; вердикт "чисто" при несведенных Major невозможен;
- "с пробелами" - часть проверок не выполнена; перечень пробелов обязателен.

Разделы "Проверено" и "Не проверено" заполняются всегда, в том числе пустым списком с
пояснением. Важность находок - по `severity.md`.

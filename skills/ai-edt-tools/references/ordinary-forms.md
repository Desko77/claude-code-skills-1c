# Обычные формы EDT

`ordinary_forms` читает и изменяет обычные формы в контейнере `Form.oform` открытого проекта.
Инструмент входит в основную feature AI-EDT. Раскладка и модуль хранятся отдельными записями
контейнера. Ответы инструмента имеют формат JSON.

## Адреса и каталог

Для существующей формы передать `projectName` и `formFqn=Catalog.Products.Form.ItemForm` либо
`modulePath=Catalogs/Products/Forms/ItemForm/Module.bsl` относительно `src/` проекта.
`help` не требует проекта; `audit` принимает проект без адреса формы. `describe_owner` и
`create_form` принимают `ownerFqn`, создание также принимает `name`.

`operation=help` возвращает актуальные операции, аргументы, свойства и события.

## Операции

24 операции: 6 читающих и 18 изменяющих, включая создание и импорт.

| Операции | Аргументы и результат |
|---|---|
| `audit` | Версии, записи контейнеров, размеры и round-trip раскладки всех обычных форм проекта. `details` по умолчанию false; `details=true` перечисляет формы; `limit` ограничивает списки (по умолчанию 20), но не полные счетчики. |
| `layout` | Заголовок, реквизиты, страницы, дерево элементов, привязки данных, обработчики и команды формы. |
| `inspect_layout` | Структурные находки и покрытие проверок без изменения формы. |
| `diff_form` | Сравнение раскладки, модуля и остальных записей контейнера с HEAD. `revision` называет результат получения предыдущей версии. |
| `describe_owner` | Реквизиты и табличные части владельца по `ownerFqn`. |
| `create_form` | Новая форма владельца: `ownerFqn`, `name` (при отсутствии принимается псевдоним `formName`), `purpose`, `synonym` (по умолчанию формируется из `name`), `title` (по умолчанию `synonym`), размеры и состав. |
| `import_from_infobase` | Импорт контейнера формы из ИБ. `module=project` (умолчание) сохраняет модуль проекта, `module=infobase` использует модуль из ИБ; `applicationId` выбирает приложение; при отсутствии используется приложение проекта по умолчанию. |
| `set_property` | `property` и аргументы свойства; `elementName` адресует элемент. |
| `bind_handler`, `unbind_handler` | `event` формы или `elementName`; `procedure` задает обработчик (по умолчанию `<element><event>`, для события формы - само событие); `stub` по умолчанию true, поэтому процедура, которой нет в модуле, добавляется с измеренными параметрами, если не передать `stub=false`; если сигнатура события отсутствует в измеренных данных, заглушка не создается. Снятие привязки не удаляет процедуру модуля. |
| `add_element` | `type`, `name`, `parent`, `page`, координаты `left`/`top`/`right`/`bottom` либо `width`/`height`, допустимый `data`, `caption` (при отсутствии принимается `title`) и `tooltip`. |
| `remove_element` | `elementName`; зависимые источники команд обрабатываются с явным `cascade`. |
| `move_element` | `elementName`, `parent`, `page`; координаты сохраняются, геометрические привязки к разделенным переносом элементам снимаются в обоих направлениях и перечисляются в `anchorsRemoved`. |
| `add_page`, `remove_page` | `add_page`: `name` (обязателен), `title`, `parent`; `remove_page`: `name`, `parent`. Страница формы или панели `parent`; удаление последней или непустой страницы возвращает отказ. |
| `add_column`, `remove_column` | `elementName` таблицы и `name` колонки; создание принимает `caption` (при отсутствии принимается `title`), `data`, `type` (`String`, `Number`, `Date` или `Boolean`, если привязка данных не определяет тип), `width`, `editable` (по умолчанию true; явное значение, противоречащее выбранному `control`, отклоняется), `control` (по умолчанию `field`, с `editable=false` - `none`). |
| `add_command_panel` | `name`, координаты `left`/`top`/`right`/`bottom` либо `width`/`height` (по умолчанию left=8, top=8, right=left+400, bottom=top+25), `parent`, `page`, `actionSource` и `autoFill` (по умолчанию true при указанном источнике, false без него и при `none`). |
| `add_button`, `remove_button` | `panel`, `name`; создание: `caption` (по умолчанию - имя кнопки; кнопка стандартного действия сохраняет текст, который дает платформа, и принимает `caption` как подсказку), `procedure` со `stub` (по умолчанию false) либо стандартное `action`, `picture` (только с `action`, индекс словаря 0..3; по умолчанию - картинка, которую корпус замеров чаще всего записывает для этого действия), `parent` подменю и `before` (кнопка того же блока). |
| `add_submenu`, `add_separator` | `panel`, `name`, `parent`, `before`; подменю также принимает `caption` (по умолчанию `name`). |
| `set_action_source` | `panel`, `table`, `autoFill`; `table=none` очищает источник команд; `autoFill` по умолчанию true при указанной таблице и false при `none`, явный аргумент задает свое значение. |
| `help` | Каталог операций, свойств и событий. |

## Создание и оформление

`create_form` принимает `purpose=ItemForm|ListForm|ChoiceForm|FolderForm|RecordForm|RecordSetForm|None`.
По умолчанию объект получает `ItemForm`, регистр - `ListForm`. `setAsDefault=true` назначает
форму основной. `width` - 500..1000 (по умолчанию 500, при двух колонках 820), `height` - 350..700 (по умолчанию по содержимому, не меньше 350); `columns=1|2|auto` (по умолчанию auto: 2, если форма выводит шапку и в ней больше 12 реквизитов, иначе 1), `tabularSections` - `pages|below` (по умолчанию pages при двух и более табличных частях, иначе below); `withFields`, `withTables`, `withCommands` задают состав.
`withFields` по умолчанию true для `ItemForm`, `FolderForm` и `RecordForm`; `withTables` - true
только для `ItemForm` с табличными частями. `withCommands` по умолчанию true, кроме `purpose=None`,
где значение false. `setAsDefault` по умолчанию false.
Аргумент `language` задает язык локализованного текста. Для `create_form` и `describe_owner` при отсутствии аргумента используется язык конфигурации по умолчанию, с резервным `ru`; для правки раскладки по умолчанию используется `ru`. Предпросмотр - `dryRun=true`.

Запись раскладки принимает версии 25/26/27. Виды `add_element`: `Label`, `Field`, `Button`,
`CheckBox`, `Group`, `Panel`, `Table`, `RadioBtn`, `Separator`, `Image`, `SelectField`,
`CommandPanel`, `TableField`, `FieldHtml`, `ListField`, `TextDocumentField`, `Chart`.

Свойства `set_property`:
- `title`, `caption`, `tooltip`: `value`, `language` для локализованного текста.
- `size`: `width` и/или `height` формы; `box`: `left`, `top`, `right`, `bottom` элемента либо `left`, `top`, `width`, `height` (`width` задает `right` от переданного `left`, а при его отсутствии - от текущего; `height` задает `bottom` от переданного `top`, а при его отсутствии - от текущего).
- `visible`, `enabled`, `readOnly`, `tabs`: булев `value` с применимостью по каталогу.
- `font`: `fontFamily`, `fontSize`, `bold`, `italic`, `underline`; `value=auto` возвращает
  автоматический выбор шрифта элемента.
- `textColor`, `backColor`, `borderColor`: `value=auto`, `#RRGGBB` или индекс элемента стиля.
- `alignment`: `value=left|center|right|auto` для Label, Button или Field; Field принимает `left`, `right` или `auto`.
- `format`: строка формата в `value`; пустое значение очищает формат; `language` задает язык формата (по умолчанию ru).
- `anchor`: `edge`, `value=form|none|<element>.<edge>`, `offset`.
- `editFormat`: именованный отказ без изменения позиции раскладки.

`edit_metadata operation=create_form formType=ORDINARY` направляет вызов в `ordinary_forms` до
создания управляемой формы. `ORDINARY` сравнивается без учета регистра после удаления пробелов
по краям. Передаются `projectName`, `ownerFqn`, `purpose`, `synonym`, `title`, `setAsDefault`,
`dryRun` и имя из `formName` либо `name`. Аргументы `width`, `height`, `withFields`, `withTables`,
`withCommands`, `columns`, `tabularSections`, `language` и `layout` этот маршрут отклоняет:
для них вызывать `ordinary_forms` напрямую. `CommonForm` направляется в обычный создатель,
который возвращает именованный отказ. Без явного `ORDINARY` действует прежний путь управляемой формы.

## Пресеты, сохранение и ИБ

`ordinary_forms_writes` - capability записи, а не вызываемый инструмент. Пресеты с запретом
записи отклоняют все изменяющие операции, включая `dryRun`, до разрешения проекта. Чтение доступно,
если сам инструмент не выключен. В разрешающем запись пресете `dryRun` не изменяет проект.
У импорта предварительная проверка проверяет адрес формы, ее наличие в модели владельца и
наличие контейнера проекта при `module=project`, без экспорта и временного каталога. Выбор
приложения, экспорт, проверка контейнера и обработчиков выполняются при настоящем импорте.

Модуль обычной формы адресуется стандартными `read_module_source`, `read_method_source`,
`get_module_structure`, `list_modules`, `write_module_source`, `diff_module` и
`code_search operation=text_search`. При записи модуля раскладка и неизвестные записи сохраняются
побайтно. При изменении только раскладки модуль сохраняется; создание заглушки обработчика может
явно изменить и модуль. Неизмененный контейнер возвращает исходные байты.
`handlerChanges=warn|refuse` управляет удалением процедур, на которые еще ссылается форма.

Перед заменой отличающегося текста запись сравнивает изменяемую запись контейнера с прочитанной
версией. Если раскладка или заменяемый модуль изменились после исходного чтения, операция
возвращает отказ с предложением перечитать форму. Незаменяемые записи сохраняются из последней
прочитанной версии контейнера; повторная запись того же текста не изменяет файл.

`import_from_infobase` импортирует все записи экспортированного контейнера; `module=project`
заменяет только запись модуля модулем проекта. Запись выполняется при различии байтов собранного
контейнера и контейнера проекта, включая добавление, изменение или удаление неизвестной записи
при равных текстах раскладки и модуля. Полное равенство байтов означает отсутствие изменений.

`import_from_infobase` сравнивает весь контейнер проекта с байтами, прочитанными до экспорта.
Изменение, удаление или создание контейнера за время экспорта возвращает отказ, в том числе
для результата без изменения текста. Финальный writer повторяет побайтовую проверку перед
записью. Это оптимистическая проверка, не атомарный compare-and-swap операционной системы.

Доверенный ответ `/health` содержит `ordinaryFormsRegistered` независимо от видимости инструмента
и разрешений записи. Self-update одного сеанса для совместной поставки подтверждает регистрацию
после перезапуска. Без подтверждения результат ненулевой, в том числе когда health возвращает
только неавторизованные данные доступности; в этом случае требуется отдельная авторизованная
проверка runtime.

Запись, изменяющая контейнер, возвращает отказ при подключенном текстовом буфере редактора
с несохраненными изменениями. Проверка применяется к модулю, раскладке, импорту и финальной
записи создаваемого контейнера. Перед повтором сохраните или отмените изменения редактора.

Запись изменяет проект и помечает владельца для следующего обновления ИБ, но не обновляет ИБ.
Затем выполнить `diagnostics operation=validate_for_export` и
`infobase_admin operation=update_database`. Диагностики проекта не заменяют платформенную проверку
модуля обычной формы; индексные инструменты сообщают неполноту охвата таких модулей.

## Результат inspect_layout

`findings` содержит `check`, `severity`, `subject`, `detail`; счетчики - `findingCount`,
`errorCount`, `warningCount`, `elementCount`. `coverage` содержит `check`, `status`, `detail`;
статусы - `performed`, `partial`, `notPerformed`. `note` поясняет неполноту проверки.

Проверяются дубли имен и идентификаторов, отсутствующие цели страниц, привязок данных,
обработчиков, источников команд и якорей, циклы якорей и невалидные прямоугольники.
Пересечения соседних элементов одной страницы и выход за родителя - предупреждения;
рамки Group/Panel исключаются из пар пересечения. Отсутствие находок при частичном покрытии
не подтверждает корректность всей формы. Инспектор не изменяет форму.

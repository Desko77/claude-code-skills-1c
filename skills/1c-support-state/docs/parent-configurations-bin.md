# Формат Ext/ParentConfigurations.bin

Файл состояния поддержки в XML-выгрузке конфигурации 1С. Формат восстановлен по наблюдениям на реальных выгрузках: поля `X` и `f2` до конца не расшифрованы, описание ниже покрывает то, что стабильно воспроизводится.

## Расположение и состояния существования

```
<корень выгрузки конфигурации>/
    Ext/
        ParentConfigurations.bin
```

| Состояние конфигурации | Файл | Размер |
|------------------------|------|--------|
| На поддержке | есть | от сотен КБ до единиц МБ |
| Поддержка снята полностью | есть, усечен | единицы-десятки байт; порог распознавания в скриптах: <= 32 байта |
| Своя конфигурация (без вендора) | нет | - |
| Расширение (CFE) | нет | признак расширения - `ConfigurationExtensionPurpose` в Configuration.xml |

## Кодировка и контейнер

Несмотря на расширение `.bin`, содержимое - ТЕКСТ в UTF-8 с BOM (`EF BB BF`). При записи скрипт всегда нормализует файл к "с BOM" (чтение терпимо к обоим вариантам). GUID в файле - строчные hex (наблюдение на всех образцах); скрипты ищут строчный шаблон `[0-9a-f-]{36}` и приводят целевой uuid к нижнему регистру.

Контейнер - фигурноскобочный формат 1С: одна пара `{ }` на весь файл, элементы через запятую, без вложенных скобок. Строки в двойных кавычках, внутренняя кавычка удваивается (`"Фирма ""1С"""`).

```
{6,G,K,
    <блок поставщика 1>
    0,0
    <блок поставщика 2>
    ...
    <блок поставщика K>}
```

- `6` - маркер формата (обязателен, скрипты проверяют `^{6,`).
- `G` - глобальный флаг "возможность изменения" (см. ниже).
- `K` - число конфигураций поставщика на поддержке (обычно 1).
- Между блоками поставщиков - разделитель `0,0` (после последнего блока его нет).

## Глобальный флаг G

| G | Смысл |
|---|-------|
| 0 | Изменение конфигурации ВКЛЮЧЕНО - действуют пообъектные правила f1 |
| 1 | Изменение ЗАПРЕЩЕНО целиком - вся конфигурация read-only, f1 у всех объектов наблюдается равным 1 (неинформативен) |

## Блок поставщика

```
guidA, X, guidПоставщика, "версия", "вендор", "имя", count,
   f1,f2,<uuidLocal>,<uuidVendor>,
   f1,f2,<uuidLocal>,<uuidVendor>,
   ...
```

| Поле | Значение |
|------|----------|
| `guidA` | GUID блока; меняется от выгрузки к выгрузке (не стабильный ключ) |
| `X` | флаг; во всех наблюдениях равен `G` (смысл отдельно не подтвержден) |
| `guidПоставщика` | стабильный GUID конфигурации поставщика |
| `"версия"`, `"вендор"`, `"имя"` | версия и реквизиты конфигурации поставщика |
| `count` | число записей объектов в блоке |

Запись объекта - 4 поля: `f1, f2, uuidLocal, uuidVendor`.

- **Флаги стоят ПЕРЕД uuid**, не после - наивный шаблон "uuid,uuid,цифры" дает неверный разбор.
- `uuidLocal` - uuid объекта в текущей конфигурации (= атрибут `uuid` корневого элемента XML-файла объекта).
- `uuidVendor` - uuid в конфигурации поставщика; при одиночной поддержке обычно совпадает с `uuidLocal`.
- **Первая запись блока - корень конфигурации целиком**; при одиночной поддержке она записана ОДНИМ uuid без пары (3 поля вместо 4).
- Записи есть и на подчиненные элементы (реквизиты, табличные части, формы) - записей значительно больше, чем объектов верхнего уровня.
- `f2` во всех наблюдениях равен 0; скрипты ищут буквальный шаблон `f1,0,uuid` и записи с `f2 <> 0` не увидят (ограничение реализации, не факт формата).

## Пообъектное правило f1 (при G = 0)

| f1 | Правило 1С | Правка |
|----|-----------|:------:|
| 0 | объект не редактируется (на замке) | нет |
| 1 | редактируется с сохранением поддержки | да |
| 2 | снят с поддержки / не входит в поддержку данного поставщика | да |

## Несколько поставщиков (K > 1)

Один и тот же объект (по `uuidLocal`) может входить в несколько блоков с разными `f1`. Консервативная свертка при чтении: объект считается "на замке", если хотя бы у одного поставщика `f1 = 0` (минимум по вхождениям). Точная семантика Конфигуратора при конфликте не подтверждена.

Ограничение переключения: `-Set` меняет `f1` объекта сквозной заменой по всему файлу - во ВСЕХ блоках одинаково. Раздельная настройка правила по поставщикам этим инструментом не поддерживается.

## Семантика операций скрипта

- `-Capability on` записывает `G = 0` и приводит `X` каждого блока и `f1` каждой записи к 0 (все на замке - поведение, наблюдаемое у Конфигуратора при включении возможности изменения).
- `-Capability off` записывает `G = 1` и приводит `X`/`f1` к 1.
- `-Set editable|off-support|locked` меняет `f1` записей объекта на 1|2|0 соответственно.
- No-op ситуации (не на поддержке, поддержка снята полностью, уже в целевом состоянии, объект не найден) завершаются кодом 0 БЕЗ перезаписи файла.

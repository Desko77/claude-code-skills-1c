# Библиотека готовых BSL-заготовок для execute_code

Параметризованные копипаст-готовые скрипты типовых операций с объектами КД 2.0
через MCP-toolkit. Типовые одноразовые probe/diag/check/fix-скрипты почти
всегда - вариации заготовок ниже.

## Правила пользования библиотекой

1. **НЕ плодить одноразовые файлы `_probe_*` / `_diag_*` / `_check_*`.**
   Сначала взять заготовку отсюда и подставить параметры.
2. Параметры помечены `<ПОДСТАВИТЬ:...>` - заменить текстуально до отправки.
3. Понадобилась новая устойчивая операция (повторится в этой или другой задаче) -
   добавить ее заготовкой СЮДА, а не в новый одноразовый файл.
4. Действительно одноразовый отладочный черновик - класть только в `tools/_tmp/`
   рабочего каталога КД и чистить после задачи.
5. Запуск: сохранить BSL во временный файл и `python kd_exec.py code < file.bsl`
   (транспорт curl, см. troubleshooting.md раздел «Транспорт»). В заготовках
   `Запрос.Текст` однострочный - это работает в любом канале; многострочник
   с `|` выживает только при передаче через kd_exec.py (реальные переносы строк),
   при ручной склейке JSON ломается.
6. Все заготовки - линейный top-level код без `Процедура`/`Функция` (ограничение
   `execute_code` = `Выполнить()`), результат в переменной `Результат`.
   Пишущие заготовки идемпотентны: повторный запуск не создает дублей.

## 1. Список ПКО конвертации

**Когда использовать:** обзор правил конвертации - какие ПКО есть, типы
источник/приемник, порядок, флаги поиска. Перед правкой флагов, диагностикой
«объект не найден», сверкой покрытия.

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
Если Конв.Пустая() Тогда
    ВызватьИсключение "Конвертация не найдена";
КонецЕсли;
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ Ссылка КАК Сс, Наименование КАК Нм, ТипИсточника КАК ТИ, ТипПриемника КАК ТП, Порядок КАК Пор, НеЗамещать КАК НЗ, СинхронизироватьПоИдентификатору КАК СинхрИд, ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли КАК ПродПоиск, НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска КАК НеСозд ИЗ Справочник.ПравилаКонвертацииОбъектов ГДЕ Владелец = &Конв И НЕ ЭтоГруппа И НЕ ПометкаУдаления УПОРЯДОЧИТЬ ПО Порядок";
Запрос.УстановитьПараметр("Конв", Конв);
Текст = "";
К = 0;
Выб = Запрос.Выполнить().Выбрать();
Пока Выб.Следующий() Цикл
    К = К + 1;
    Текст = Текст + Строка(Выб.Пор) + "|" + Выб.Нм + "|" + Выб.ТИ + " -> " + Выб.ТП
        + "|UUID=" + XMLСтрока(Выб.Сс)
        + "|НеЗамещать=" + Строка(Выб.НЗ) + "|СинхрИд=" + Строка(Выб.СинхрИд)
        + "|ПродПоиск=" + Строка(Выб.ПродПоиск) + "|НеСоздавать=" + Строка(Выб.НеСозд) + ПС;
КонецЦикла;
Результат = Текст + "ИТОГО ПКО: " + Строка(К);
```

## 2. Список ПКС конкретного ПКО

**Когда использовать:** состав правил свойств ПКО - что во что мапится, каким
правилом конвертации, какие поля поисковые, где алгоритмы, что отключено или
помечено на удаление, иерархия групп-табчастей.

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
ПКО = Справочники.ПравилаКонвертацииОбъектов.НайтиПоНаименованию("<ПОДСТАВИТЬ:НаименованиеПКО>", Истина, , Конв);
Если ПКО.Пустая() Тогда
    ВызватьИсключение "ПКО не найдено";
КонецЕсли;
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ ИмяИсточника КАК ИИ, ИмяПриемника КАК ИП, ТипИсточника КАК ТИ, ТипПриемника КАК ТП, ИмяПравилаКонвертации КАК ПрК, Поиск КАК Пск, Отключить КАК Откл, ПометкаУдаления КАК ПУ, ЭтоГруппа КАК Гр, Родитель КАК Род, АлгоритмПередВыгрузкойСвойства КАК Алг ИЗ Справочник.ПравилаКонвертацииСвойств ГДЕ Владелец = &ПКО УПОРЯДОЧИТЬ ПО Родитель, ИмяПриемника";
Запрос.УстановитьПараметр("ПКО", ПКО);
Текст = "";
К = 0;
Выб = Запрос.Выполнить().Выбрать();
Пока Выб.Следующий() Цикл
    К = К + 1;
    Метки = ?(Выб.Гр, "[ТЧ/ГРУППА]", "") + ?(Выб.Пск, "[ПОИСК]", "") + ?(Выб.Откл, "[ОТКЛ]", "")
        + ?(Выб.ПУ, "[УДАЛ]", "") + ?(ПустаяСтрока(Выб.Алг), "", "[АЛГ]");
    Род = ?(ЗначениеЗаполнено(Выб.Род), " (в группе '" + Строка(Выб.Род) + "')", "");
    Текст = Текст + Выб.ИИ + " -> " + Выб.ИП + " |" + Выб.ТИ + " -> " + Выб.ТП
        + ?(ПустаяСтрока(Выб.ПрК), "", " |ПКО:" + Выб.ПрК) + Род + " " + Метки + ПС;
КонецЦикла;
Результат = "ПКО: " + Строка(ПКО) + ПС + Текст + "ИТОГО ПКС: " + Строка(К);
```

## 4. Дамп обработчиков событий ПКО

**Когда использовать:** прочитать тексты алгоритмов событий ПКО перед правкой
или для аудита. Индексатор `Объект["Имя"]` у объектов НЕ работает - поля
перечислены явно (все 7 событий ПКО). Для ПКС аналогично, но полей 5
(`АлгоритмПередВыгрузкойСвойства`, `АлгоритмПриВыгрузкеСвойства`,
`АлгоритмПослеВыгрузкиСвойства`, `АлгоритмПередОбработкойВыгрузки`,
`АлгоритмПослеОбработкиВыгрузки`); для Конвертации - см. перечень в architecture.md.

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
ПКО = Справочники.ПравилаКонвертацииОбъектов.НайтиПоНаименованию("<ПОДСТАВИТЬ:НаименованиеПКО>", Истина, , Конв);
Если ПКО.Пустая() Тогда
    ВызватьИсключение "ПКО не найдено";
КонецЕсли;
Текст = "ПКО: " + Строка(ПКО) + ПС;
Текст = Текст + "<<<АлгоритмПередВыгрузкойОбъекта>>>" + ПС + ПКО.АлгоритмПередВыгрузкойОбъекта + ПС;
Текст = Текст + "<<<АлгоритмПриВыгрузкеОбъекта>>>" + ПС + ПКО.АлгоритмПриВыгрузкеОбъекта + ПС;
Текст = Текст + "<<<АлгоритмПослеВыгрузкиОбъекта>>>" + ПС + ПКО.АлгоритмПослеВыгрузкиОбъекта + ПС;
Текст = Текст + "<<<АлгоритмПередЗагрузкойОбъекта>>>" + ПС + ПКО.АлгоритмПередЗагрузкойОбъекта + ПС;
Текст = Текст + "<<<АлгоритмПриЗагрузкеОбъекта>>>" + ПС + ПКО.АлгоритмПриЗагрузкеОбъекта + ПС;
Текст = Текст + "<<<АлгоритмПослеЗагрузкиОбъекта>>>" + ПС + ПКО.АлгоритмПослеЗагрузкиОбъекта + ПС;
Текст = Текст + "<<<АлгоритмПослеВыгрузкиОбъектаВФайлОбмена>>>" + ПС + ПКО.АлгоритмПослеВыгрузкиОбъектаВФайлОбмена + ПС;
Результат = Текст;
```

## 5. Поиск объекта КД по имени с учетом префикса типа

**Когда использовать:** `НайтиПоНаименованию` в `Справочник.Объекты` вернул пусто.
Наименования в теневой модели хранятся С ПРЕФИКСОМ типа
(`СправочникСсылка.Контрагенты`, `ДокументСсылка.ПоступлениеНаРасчетныйСчет`) -
заготовка перебирает известные префиксы, при неудаче ищет похожие по `ПОДОБНО`.

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
Конфигурация = Конв.Источник;  // или Конв.Приемник
ИмяКороткое = "<ПОДСТАВИТЬ:ИмяОбъектаБезПрефикса>";
Текст = "";
Префиксы = СтрРазделить("СправочникСсылка,ДокументСсылка,ПеречислениеСсылка,ПланСчетовСсылка,ПланВидовХарактеристикСсылка", ",");
Для Каждого Преф Из Префиксы Цикл
    Объ = Справочники.Объекты.НайтиПоНаименованию(Преф + "." + ИмяКороткое, Истина, , Конфигурация);
    Если НЕ Объ.Пустая() Тогда
        Текст = Текст + Строка(Объ) + " |UUID=" + XMLСтрока(Объ) + ПС;
    КонецЕсли;
КонецЦикла;
Если ПустаяСтрока(Текст) Тогда
    Запрос = Новый Запрос;
    Запрос.Текст = "ВЫБРАТЬ Наименование КАК Нм ИЗ Справочник.Объекты ГДЕ Владелец = &Конф И Наименование ПОДОБНО &Шбл";
    Запрос.УстановитьПараметр("Конф", Конфигурация);
    Запрос.УстановитьПараметр("Шбл", "%" + ИмяКороткое + "%");
    Выб = Запрос.Выполнить().Выбрать();
    Пока Выб.Следующий() Цикл
        Текст = Текст + "похожее: " + Выб.Нм + ПС;
    КонецЦикла;
КонецЕсли;
Результат = ?(ПустаяСтрока(Текст), "НЕ найдено: " + ИмяКороткое, Текст);
```

Смежное: `Свойства` ищутся по КОРОТКОМУ имени реквизита с Владельцем-Объектом
(`НайтиПоНаименованию("ИНН", Истина, , Объект)` - Владелец 4-й параметр,
3-й Родитель пропускается). Поиск ПКО по полю `Код` (строка фиксированной длины
с trailing-пробелами) - только `Код ПОДОБНО &Шаблон` с `Шаблон = Имя + "%"`.

## 6. Установка флага у ПКО (массово по списку типов)

**Когда использовать:** включить/снять поведенческий флаг ПКО - `НеЗамещать`,
`СинхронизироватьПоИдентификатору`,
`ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли`,
`НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска`,
`ИспользоватьБыстрыйПоискПриЗагрузке` и другие boolean-реквизиты
(полный список - architecture.md). Имя флага подставляется ТЕКСТУАЛЬНО -
индексатор по строке у объектов не работает.

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
Типы = Новый Массив;
Типы.Добавить("<ПОДСТАВИТЬ:ТипИсточникаПКО>");  // например "СправочникСсылка.Контрагенты"; добавить нужные
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ Ссылка КАК Сс, Источник КАК Ист ИЗ Справочник.ПравилаКонвертацииОбъектов ГДЕ Владелец = &Конв И НЕ ПометкаУдаления";
Запрос.УстановитьПараметр("Конв", Конв);
Выб = Запрос.Выполнить().Выбрать();
Текст = "";
Счет = 0;
Пока Выб.Следующий() Цикл
    Если Типы.Найти(Строка(Выб.Ист)) = Неопределено Тогда
        Продолжить;
    КонецЕсли;
    Объект = Выб.Сс.ПолучитьОбъект();
    Объект.<ПОДСТАВИТЬ:ИмяФлага> = Истина;
    Объект.Записать();
    Счет = Счет + 1;
    Текст = Текст + "OK: " + Строка(Выб.Ист) + ПС;
КонецЦикла;
Результат = Текст + "ИТОГО изменено ПКО: " + Строка(Счет);
```

Для одного ПКО по наименованию - вместо запроса:
`Объект = Справочники.ПравилаКонвертацииОбъектов.НайтиПоНаименованию("...", Истина, , Конв).ПолучитьОбъект();`.

## 7. Создание/правка ПКС со ссылкой на Свойство

**Когда использовать:** добавить или поправить правило свойства. ОБЯЗАТЕЛЬНО
через ссылки `Справочник.Свойства` (текстовые имена без ссылок КД сбрасывает
в пустые - troubleshooting.md «Программное создание ПКС»). Идемпотентно:
существующая ПКС правится, не дублируется.

```bsl
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
ПКО = Справочники.ПравилаКонвертацииОбъектов.НайтиПоНаименованию("<ПОДСТАВИТЬ:НаименованиеПКО>", Истина, , Конв);
ИмяИст = "<ПОДСТАВИТЬ:ИмяРеквизитаИсточника>";
ИмяПрм = "<ПОДСТАВИТЬ:ИмяРеквизитаПриемника>";
СвИст = Справочники.Свойства.НайтиПоНаименованию(ИмяИст, Истина, , ПКО.Источник);
СвПрм = Справочники.Свойства.НайтиПоНаименованию(ИмяПрм, Истина, , ПКО.Приемник);
Если СвИст.Пустая() ИЛИ СвПрм.Пустая() Тогда
    ВызватьИсключение "Свойство не найдено в теневой модели: ист_пусто=" + Строка(СвИст.Пустая()) + " прм_пусто=" + Строка(СвПрм.Пустая());
КонецЕсли;
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка ИЗ Справочник.ПравилаКонвертацииСвойств ГДЕ Владелец = &ПКО И ИмяПриемника = &Имя И НЕ ПометкаУдаления";
Запрос.УстановитьПараметр("ПКО", ПКО);
Запрос.УстановитьПараметр("Имя", ИмяПрм);
Выб = Запрос.Выполнить().Выбрать();
Если Выб.Следующий() Тогда
    ПКС = Выб.Ссылка.ПолучитьОбъект();
Иначе
    ПКС = Справочники.ПравилаКонвертацииСвойств.СоздатьЭлемент();
    ПКС.Владелец = ПКО;
КонецЕсли;
ПКС.Источник = СвИст;
ПКС.Приемник = СвПрм;
// ПКС.ПравилоКонвертации = <ссылка на ПКО>;  // только для ссылочного типа реквизита
// ПКС.Поиск = Истина;                        // только для поля поиска НСИ
// ПКС.АлгоритмПередВыгрузкойСвойства = "Значение = ...;";  // если нужен алгоритм
ПКС.Записать();  // ПередЗаписью сам заполнит Имя/Тип/Вид/Наименование/Порядок из ссылок
Если ПустаяСтрока(ПКС.ИмяПриемника) Тогда
    ВызватьИсключение "ПКС записалась мусором (пустое ИмяПриемника) - свойство не резолвится";
КонецЕсли;
Результат = "OK " + Строка(ПКС.Ссылка) + " |" + ПКС.ИмяИсточника + " -> " + ПКС.ИмяПриемника;
```

ПКС табличной части - через `СоздатьГруппу()` вместо `СоздатьЭлемент()`
(`ЭтоГруппа` напрямую присвоить нельзя, см. troubleshooting.md).

## 8. ПКС поиска по реквизиту-ГУИД на все НСИ-ПКО (массово)

**Когда использовать:** обеспечить поиск существующих элементов НСИ в приемнике
по бизнес-ключу (реквизит-ГУИД) сразу для всех справочников конвертации.
См. идиому И3 и troubleshooting.md «Поиск НСИ по ГУИД».

```bsl
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
ИмяГУИД = "<ПОДСТАВИТЬ:ИмяРеквизитаГУИД>";
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ Ссылка КАК Сс, Источник КАК Ист, Приемник КАК Прм, Наименование КАК Имя ИЗ Справочник.ПравилаКонвертацииОбъектов ГДЕ Владелец = &Конв И НЕ ПометкаУдаления И ТипПриемника ПОДОБНО ""СправочникСсылка%""";
Запрос.УстановитьПараметр("Конв", Конв);
Выб = Запрос.Выполнить().Выбрать();
Создано = 0;
Лог = "";
Пока Выб.Следующий() Цикл
    СвИст = Справочники.Свойства.НайтиПоНаименованию(ИмяГУИД, Истина, , Выб.Ист);

        Продолжить;
    КонецЕсли;
    ЗапросД = Новый Запрос;
    ЗапросД.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка ИЗ Справочник.ПравилаКонвертацииСвойств ГДЕ Владелец = &ПКО И ИмяПриемника = &Имя";
    ЗапросД.УстановитьПараметр("ПКО", Выб.Сс);
    ЗапросД.УстановитьПараметр("Имя", ИмяГУИД);
    Если ЗапросД.Выполнить().Выбрать().Следующий() Тогда
        Лог = Лог + " EXISTS[" + Выб.Имя + "]";
        Продолжить;
    КонецЕсли;
    ПКС = Справочники.ПравилаКонвертацииСвойств.СоздатьЭлемент();
    ПКС.Владелец = Выб.Сс;
    ПКС.Источник = СвИст;
    ПКС.Приемник = СвПрм;
    ПКС.Поиск = Истина;
    ПКС.Записать();
    Создано = Создано + 1;
    Лог = Лог + " OK[" + Выб.Имя + "]";
КонецЦикла;
Результат = "Создано ПКС поиска=" + Строка(Создано) + " |" + Лог;
```

## 10. Upsert ПКЗ с гарантией Значений

**Когда использовать:** добавить/обновить маппинги значений перечислений.
Заготовка сама досоздает недостающие записи `Справочник.Значения` (теневая
модель метаданных нередко отстает от живой конфигурации). У перечислений
Владелец Значения = сам Объект-перечисление (2 уровня, troubleshooting.md).

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
ПКО = Справочники.ПравилаКонвертацииОбъектов.НайтиПоНаименованию("<ПОДСТАВИТЬ:НаименованиеПКО>", Истина, , Конв);
Если ПКО.Пустая() Тогда
    ВызватьИсключение "ПКО-перечисление не найдено";
КонецЕсли;
Пары = Новый Массив;
// формат: "ИмяЗначенияИсточника|ИмяЗначенияПриемника"
Пары.Добавить("<ПОДСТАВИТЬ:ИмяИст>|<ПОДСТАВИТЬ:ИмяПрм>");

Для Каждого Пара Из Пары Цикл
    Поз = СтрНайти(Пара, "|");

    ИмяПрм = Сред(Пара, Поз + 1);

    Если ЗнИст.Пустая() Тогда
        НЗ = Справочники.Значения.СоздатьЭлемент();
        НЗ.Владелец = ПКО.Источник;
        НЗ.Наименование = ИмяИст;
        НЗ.Записать();
        ЗнИст = НЗ.Ссылка;
        Текст = Текст + "+Значение ист: " + ИмяИст + ПС;
    КонецЕсли;
    ЗнПрм = Справочники.Значения.НайтиПоНаименованию(ИмяПрм, Истина, , ПКО.Приемник);
    Если ЗнПрм.Пустая() Тогда
        НЗ = Справочники.Значения.СоздатьЭлемент();
        НЗ.Владелец = ПКО.Приемник;
        НЗ.Наименование = ИмяПрм;
        НЗ.Записать();
        ЗнПрм = НЗ.Ссылка;
        Текст = Текст + "+Значение прм: " + ИмяПрм + ПС;
    КонецЕсли;
    Запрос = Новый Запрос;
    Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка ИЗ Справочник.ПравилаКонвертацииЗначений ГДЕ Владелец = &ПКО И Источник = &Ист";
    Запрос.УстановитьПараметр("ПКО", ПКО);
    Запрос.УстановитьПараметр("Ист", ЗнИст);
    Выб = Запрос.Выполнить().Выбрать();
    Если Выб.Следующий() Тогда
```

## 11. Замена маркированного блока в обработчике ПКО

**Когда использовать:** итеративная доработка алгоритма события (вставка/замена
своего блока кода) без риска затереть остальной обработчик. Блок обрамляется
маркерами; повторный запуск заменяет блок целиком. Текущий текст смотреть
заготовкой 4.

```bsl
ПС = Символы.ПС;
Конв = Справочники.Конвертации.НайтиПоНаименованию("<ПОДСТАВИТЬ:ИмяКонвертации>");
ПКО = Справочники.ПравилаКонвертацииОбъектов.НайтиПоНаименованию("<ПОДСТАВИТЬ:НаименованиеПКО>", Истина, , Конв);
Если ПКО.Пустая() Тогда
    ВызватьИсключение "ПКО не найдено";
КонецЕсли;
МаркерСтарт = "//{++ <ПОДСТАВИТЬ:МеткаЗадачи>";
МаркерКонец = "//}-- <ПОДСТАВИТЬ:МеткаЗадачи>";
НовыйБлок = "<ПОДСТАВИТЬ:КодВставки>";  // многострочный код собирать конкатенацией через ПС
Об = ПКО.ПолучитьОбъект();
Алг = Об.АлгоритмПослеЗагрузкиОбъекта;  // или другое поле события из заготовки 4
Поз1 = СтрНайти(Алг, МаркерСтарт);
Если Поз1 = 0 Тогда
    Об.АлгоритмПослеЗагрузкиОбъекта = Алг + ПС + МаркерСтарт + ПС + НовыйБлок + ПС + МаркерКонец;
Иначе
    Поз2 = СтрНайти(Алг, МаркерКонец);
    Если Поз2 = 0 Тогда
        ВызватьИсключение "Маркер конца не найден - блок поврежден, разобраться вручную";
    КонецЕсли;
    Об.АлгоритмПослеЗагрузкиОбъекта = Лев(Алг, Поз1 - 1) + МаркерСтарт + ПС + НовыйБлок + ПС + Сред(Алг, Поз2);
КонецЕсли;
Об.Записать();
Результат = "OK, длина обработчика: " + Строка(СтрДлина(Об.АлгоритмПослеЗагрузкиОбъекта));
```

## Идиомы передачи значений через ПКС

### И1. Значение перечисления - строкой-именем, без ПКО и ПКЗ

**Когда использовать:** реквизит приемника - перечисление, соответствие
вычислимо кодом или имена значений совпадают (тождественные перечисления).

В `АлгоритмПередВыгрузкойСвойства` присвоить `Значение` СТРОКУ - имя значения
перечисления приемника:

```bsl
Значение = "ОплатаПокупателя";  // имя значения в перечислении ПРИЕМНИКА
```

КД при загрузке сама подставит значение по имени в перечислении из типа
реквизита-приемника. `ПравилоКонвертации` у ПКС оставить ПУСТЫМ - для
тождественных перечислений ПКО-перечисление и ПКЗ не нужны. ПКО+ПКЗ нужны
только для табличного N:M маппинга без вычислимой логики. Развернутый пример:
troubleshooting.md, раздел «Передача значения перечисления приемника без ПКО».

### И2. Строка в ссылочный реквизит - только через строку-прокси

**Когда использовать:** на выгрузке известна строка (имя, код, представление),
а реквизит приемника - ссылка на справочник/ПВХ приемной базы.

Напрямую НЕЛЬЗЯ: подстановка по имени работает только для перечислений (И1).
Для прочих ссылочных типов КД ожидает либо ПКО (выгрузка объекта по правилу),
либо поля поиска. Паттерн «строка-прокси с последующим резолвом»:

1. На выгрузке ПКС кладет строку в СТРОКОВЫЙ реквизит-прокси приемника
   (служебный реквизит или временно свободное строковое поле с
   маркером-префиксом, чтобы отличить от штатного содержимого).
2. В `АлгоритмПослеЗагрузкиОбъекта` ПКО приемника строка резолвится в ссылку
   (`НайтиПоНаименованию` / `НайтиПоКоду` / `Перечисления.Х[Имя]` в Попытке)
   и прокси-поле очищается.

Пример: вид операции документа передается строкой в свободном реквизите
`КодВалютнойОперации = "ВидОп:<ИмяЗначения>"`; обработчик ПослеЗагрузки парсит
префикс `ВидОп:`, ставит `Объект.ВидОперации = Перечисления.Х[Имя]` в Попытке
и очищает `КодВалютнойОперации`.

### И3. Поиск НСИ - по реквизиту-ГУИД, не по внутреннему GUID ссылки

**Когда использовать:** НСИ в базах ведется независимо, нужен поиск
существующих элементов приемника без создания новых.

Правильно: ПКС по реквизиту-ГУИД с `Поиск = Истина` (заготовка 8) + НСИ-пресет
ПКО (заготовка 9). НЕ полагаться на внутренний GUID ссылки
(`СинхронизироватьПоИдентификатору`): при независимом ведении НСИ внутренние
GUID в базах РАЗНЫЕ, а поиск по идентификатору без флага
`ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли` перебивает поля
поиска - объект «не находится». Матрица поведения флагов и фикс:
troubleshooting.md, разделы «Поиск НСИ по ГУИД» и «Объекты НЕ находятся при
загрузке».

# Обновление версии информационной базы

Механизм БСП, приводящий ДАННЫЕ в соответствие новой версии конфигурации:
обработчики обновления, порционная обработка больших объемов, отложенное
обновление. Работает после того, как платформа обновила структуру базы.

Не путать с обновлением конфигурации: то доставляет новую версию, это переносит
данные под нее.

## Модули механизма

| Модуль | Роль | Контексты |
|---|---|---|
| `ОбновлениеИнформационнойБазы` | программный интерфейс | сервер, толстый клиент, внешнее соединение |
| `ОбновлениеИнформационнойБазыПереопределяемый` | точка расширения сервера | сервер, толстый клиент, внешнее соединение |
| `ОбновлениеИнформационнойБазыКлиентПереопределяемый` | точка расширения клиента: что показать до и после перехода | тонкий и толстый клиент |
| `ОбновлениеИнформационнойБазыБСП`, `ОбновлениеИнформационнойБазыБСД` | обработчики самой библиотеки, не прикладной код | сервер |
| `ОбновлениеИнформационнойБазыСлужебный` и еще пять | внутренняя реализация библиотеки | - |

**Собственные обработчики объявляются НЕ в переопределяемом модуле.** Каждая
подсистема заводит у себя процедуру `ПриДобавленииОбработчиковОбновления(Обработчики)`
и наполняет переданную таблицу - так устроены и обработчики самой библиотеки,
проверено по ее исходникам. Переопределяемый модуль отвечает за порядок и за
события вокруг обновления, а не за перечень обработчиков.

## Сценарии

### 1. Объявить обработчик обновления

**Задача:** при переходе на новую версию заполнить новый реквизит у существующих
документов.

**Механизм:** процедура `ПриДобавленииОбработчиковОбновления(Обработчики)` в общем
модуле своей подсистемы. Библиотека собирает обработчики со всех подсистем и
выполняет их по версиям.

**Ключевые свойства строки обработчика** (взято из обработчиков библиотеки):

- `Версия` - версия конфигурации, при переходе на которую обработчик выполняется.
- `Идентификатор` - `УникальныйИдентификатор`, обязателен для отложенных.
- `Процедура` - полное имя процедуры, которая делает работу.
- `РежимВыполнения` - когда выполнять: сразу либо `"Отложенно"`.
- `ПроцедураЗаполненияДанныхОбновления` - что зарегистрировать к обработке, для
  отложенного режима.
- `ЧитаемыеОбъекты` и `ИзменяемыеОбъекты` - на чем обработчик работает; по ним
  библиотека строит порядок и разводит блокировки.

**Пример:**

```bsl
// Общий модуль своей подсистемы.
Процедура ПриДобавленииОбработчиковОбновления(Обработчики) Экспорт

    Обработчик = Обработчики.Добавить();
    Обработчик.Версия = "1.2.3.4";
    Обработчик.Идентификатор = Новый УникальныйИдентификатор("00000000-0000-0000-0000-000000000000");
    Обработчик.Процедура = "Документы.РасходТовара.ЗаполнитьНовыйРеквизит";
    Обработчик.РежимВыполнения = "Отложенно";
    Обработчик.ПроцедураЗаполненияДанныхОбновления = "Документы.РасходТовара.ЗарегистрироватьКОбработке";
    Обработчик.ЧитаемыеОбъекты = "Документ.РасходТовара";
    Обработчик.ИзменяемыеОбъекты = "Документ.РасходТовара";

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Не менять данные в модуле сеанса или при начале работы системы: обновление
  данных идет один раз по версии, а не при каждом входе.
- Идентификатор обработчика не переиспользуется: по нему библиотека отличает уже
  выполненный обработчик от нового.
- Обработчик выполняется ОДИН раз на переход между версиями. Повторный запуск
  требует сброса состояния, а не повторной установки.

### 2. Обработать большой объем порциями

**Задача:** заполнить реквизит у миллиона документов, не заблокировав базу.

**Функции:**

`ОбновлениеИнформационнойБазы.ВыбратьСсылкиДляОбработки(Очередь, ПолноеИмяОбъекта, ДополнительныеПараметры = Неопределено) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`. Сервер.

`ОбновлениеИнформационнойБазы.ВыбратьРегистраторыРегистраДляОбработки(Очередь, ПолноеИмяДокумента, ПолноеИмяРегистра, ДополнительныеПараметры = Неопределено) Экспорт`
- функция, тот же регион.

`ОбновлениеИнформационнойБазы.ВыбратьИзмеренияНезависимогоРегистраСведенийДляОбработки(Очередь, ПолноеИмяОбъекта, ДополнительныеПараметры = Неопределено) Экспорт`
- функция, тот же регион.

**Нюансы и антипаттерны:**

- Не выбирать все ссылки одним запросом без порций: отложенный обработчик обязан
  завершаться, а не работать часами в одной транзакции.
- Для каждого вида источника своя функция выборки. Регистр сведений и документ
  обрабатываются по-разному, и общей функции нет.

### 3. Узнать версию данных и версию конфигурации

**Задача:** ветвление логики по тому, с какой версии идет переход.

**Функции:**

`ОбновлениеИнформационнойБазы.ВерсияИБ(Знач ИдентификаторБиблиотеки) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`. Сервер.

`ОбновлениеИнформационнойБазы.ВерсииПодсистем() Экспорт` - функция, тот же
регион: версии всех подсистем и библиотек сразу.

**Нюансы и антипаттерны:**

- Не читать версию из константы или регистра напрямую: у каждой библиотеки в
  конфигурации своя версия, и одной константой они не описываются.
- Версия ИБ это версия ДАННЫХ, а не версия конфигурации. До выполнения
  обработчиков они различаются, и на этом различии механизм и работает.

### 4. Выполнить свое действие вокруг обновления

**Задача:** до обновления снять блокировки, после - пересчитать итоги.

**Функции:**

`ОбновлениеИнформационнойБазыПереопределяемый.ПередОбновлениемИнформационнойБазы() Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. ХУК.

`ОбновлениеИнформационнойБазыПереопределяемый.ПослеОбновленияИнформационнойБазы(Знач ПредыдущаяВерсияИБ, Знач ТекущаяВерсияИБ, Знач ИтерацииОбновления, ВыводитьОписаниеОбновлений, Знач МонопольныйРежим) Экспорт`
- процедура, тот же регион и та же роль.

`ОбновлениеИнформационнойБазыПереопределяемый.ПриЗаполненииОбъектовПланируемыхКУдалению(Объекты) Экспорт` [3.1.11]
- процедура, тот же регион: объявляет объекты, которые будут удалены в следующих
версиях. **В 3.2.1 этого хука НЕТ** - код, реализующий его, при переходе
перестанет вызываться, и о том, что объекты планируются к удалению, библиотека
не узнает.

**Нюансы и антипаттерны:**

- Не вызывать процедуры `ОбновлениеИнформационнойБазыПереопределяемый` из
  прикладного кода: их реализуют.
- В хуке после обновления известны ОБЕ версии, прежняя и текущая. Ветвиться надо
  по ним, а не по текущей версии конфигурации.

### 5. Управлять отложенным обновлением

**Задача:** дать пользователям работать, пока данные догоняют новую версию.

**Функции:**

`ОбновлениеИнформационнойБазы.ВключитьОтключитьОтложенноеОбновление(Использование) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. Сервер.

`ОбновлениеИнформационнойБазы.ВыполнитьОбновлениеИнформационнойБазы(ВыполнятьОтложенныеОбработчики = Ложь) Экспорт`
- функция, тот же регион.

**Нюансы и антипаттерны:**

- Отложенный обработчик обязан переносить неполные данные: пользователь работает
  с базой, где часть записей уже обновлена, а часть еще нет.
- Не считать отложенное обновление завершенным по факту входа в программу: оно
  идет фоново и завершается позже.

## Различия версий

Состав модулей семейства в 3.1.11 и 3.2.1 совпадает - сверено по обеим поставкам.

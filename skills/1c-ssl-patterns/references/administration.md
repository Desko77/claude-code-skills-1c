# Администрирование: сеансы, безопасный режим, контроль работы, копирование

Четыре механизма БСП для администратора: завершение работы пользователей,
профили безопасности и выполнение кода с разрешениями, отчеты о действиях
пользователей по журналу регистрации, резервное копирование базы.

**Имена модулей здесь расходятся с названиями подсистем сильнее всего.** Проверено
по обеим поставкам:

| Подсистема называется | А модуль называется |
|---|---|
| Завершение работы пользователей | `СоединенияИБ` |
| Профили безопасности | `РаботаВБезопасномРежиме` |
| Резервное копирование ИБ | `РезервноеКопированиеИБКлиент` и семейство |
| Контроль работы пользователей | `КонтрольРаботыПользователей` (совпадает) |

Модулей `ЗавершениеРаботыПользователей` и `ПрофилиБезопасности` в библиотеке НЕТ.

## Модули

| Модуль | Механизм | Контексты |
|---|---|---|
| `СоединенияИБ` | блокировка новых сеансов, отключение активных соединений | сервер, толстый клиент, внешнее соединение |
| `РаботаВБезопасномРежиме` | запросы разрешений на внешние ресурсы и выполнение кода с ними | сервер, толстый клиент, внешнее соединение |
| `КонтрольРаботыПользователей` | отчеты о действиях по журналу регистрации | сервер, толстый клиент, внешнее соединение |
| `РезервноеКопированиеИБКлиент` и семейство из пяти модулей | резервное копирование | клиент / сервер |
| `БлокировкаРаботыСВнешнимиРесурсами` | блокировка внешних ресурсов при копировании базы | сервер |

## Сценарии

### 1. Завершить работу пользователей перед обновлением

**Задача:** заблокировать новые сеансы и отключить активные.

**Механизм:** модуль `СоединенияИБ`, регион `ПрограммныйИнтерфейс`. Сервер.
Восемь методов: блокировка начала сеансов, перечень активных соединений,
отключение.

**Нюансы и антипаттерны:**

- Не устанавливать блокировку сеансов платформенными средствами напрямую:
  библиотека показывает пользователям понятное предупреждение и дает время
  завершить работу.
- Отключение активных соединений не мгновенное: часть сеансов завершается с
  задержкой, и код обновления должен это учитывать.

### 2. Запросить разрешение на внешний ресурс

**Задача:** обработка обращается в интернет или к файлу, а в базе включены
профили безопасности.

**Функции:**

Модуль `РаботаВБезопасномРежиме`, регион `ПрограммныйИнтерфейс`. Сервер.
Запросы на использование файлов, интернета, COM и внешних компонент, а также
выполнение кода с полученными разрешениями.

**Нюансы и антипаттерны:**

- Разрешение запрашивается ДО операции и подтверждается администратором. Код,
  идущий во внешний ресурс без запроса, при включенных профилях просто упадет.
- Не отключать профили безопасности ради работы своей обработки: это снимает
  защиту со всей базы, а не с одной операции.

### 3. Настроить регистрацию доступа к данным

**Задача:** вести учет того, кто и какие данные смотрел.

**Функции:**

`КонтрольРаботыПользователей.РегистрироватьДоступКДанным() Экспорт` - функция,
регион `ПрограммныйИнтерфейс`. Сервер.

`КонтрольРаботыПользователей.УстановитьРегистрациюДоступаКДанным(РегистрироватьДоступКДанным) Экспорт`
- процедура, тот же регион.

`КонтрольРаботыПользователей.НастройкиРегистрацииСобытийДоступаКДанным() Экспорт`
и `КонтрольРаботыПользователей.УстановитьНастройкиРегистрацииСобытийДоступаКДанным(Настройки) Экспорт`
- функция и процедура, тот же регион.

**Нюансы и антипаттерны:**

- Регистрация доступа заметно нагружает журнал. Включать ее на все объекты сразу
  не следует: настройка задается по видам событий и объектам.
- Отчеты строятся ПО ЖУРНАЛУ регистрации. Очищенный журнал означает пустой отчет,
  и это не ошибка механизма.

### 4. Резервное копирование

**Задача:** предложить пользователю сделать копию перед рискованной операцией.

**Механизм:** семейство `РезервноеКопированиеИБ`. Публичный интерфейс клиентский:
копирование это действие администратора на его рабочем месте.

**Нюансы и антипаттерны:**

- Копирование доступно не во всех вариантах работы. Проверять доступность до
  показа команды обязательно.
- На время копирования работа с внешними ресурсами блокируется отдельным
  механизмом: `БлокировкаРаботыСВнешнимиРесурсами`. Иначе восстановленная копия
  начнет слать письма и обмениваться данными как рабочая база.

## Различия версий

Состав модулей всех четырех механизмов в 3.1.11 и 3.2.1 совпадает - сверено по
обеим поставкам.

## Проверка перед использованием

Имена здесь расходятся с названиями подсистем, поэтому проверка обязательна:

```bash
python skills/1c-bsp-api/scripts/bsp-api.py module СоединенияИБ
```

# Версионирование объектов

Механизм БСП, сохраняющий историю изменений объекта: кто и когда правил, что
именно изменилось, откат к прежней версии. Включается на объект метаданных, а не
на конфигурацию целиком.

## Модули механизма

| Модуль | Роль | Контексты |
|---|---|---|
| `ВерсионированиеОбъектов` | программный интерфейс: включение, настройка, встраивание в форму | сервер, толстый клиент, внешнее соединение |
| `ВерсионированиеОбъектовКлиент` | программный интерфейс клиента: открытие отчетов и настройки | тонкий и толстый клиент |
| `ВерсионированиеОбъектовПереопределяемый` | точка расширения | сервер, толстый клиент, внешнее соединение |
| `ВерсионированиеОбъектовСобытия` | обработчики подписок, записывающие версию при изменении | сервер, толстый клиент, внешнее соединение |
| `ВерсионированиеОбъектовСлужебныйВызовСервера` | внутренняя реализация библиотеки | - |

Здесь, в отличие от многих механизмов библиотеки, клиентский модуль публичный:
`ВерсионированиеОбъектовКлиент` содержит открытие отчета по версии и по
изменениям. Проверять контекст все равно надо: серверные методы вызывать с
клиента нельзя.

## Сценарии

### 1. Включить версионирование объекта из кода

**Задача:** при внедрении включить хранение истории для своего документа, не
заставляя администратора искать настройку.

**Функции:**

`ВерсионированиеОбъектов.ВключитьВерсионированиеОбъекта(ИмяОбъекта, Знач ВариантВерсионирования = Неопределено) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. Сервер.

`ВерсионированиеОбъектов.ВключеноВерсионированиеОбъекта(ИмяОбъекта) Экспорт`
- функция, тот же регион.

**Параметры:**

- `ИмяОбъекта` - `Строка`, полное имя объекта метаданных.
- `ВариантВерсионирования` - когда версия пишется: при каждой записи, при
  проведении и так далее.

**Пример:**

```bsl
&НаСервере
Процедура ВключитьИсториюПоРасходу()

    ИмяОбъекта = "Документ.РасходТовара";
    Если Не ВерсионированиеОбъектов.ВключеноВерсионированиеОбъекта(ИмяОбъекта) Тогда
        ВерсионированиеОбъектов.ВключитьВерсионированиеОбъекта(ИмяОбъекта);
    КонецЕсли;

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Не писать в регистр версий напрямую: формат хранения внутренний и меняется
  между версиями библиотеки.
- Включение действует на будущие записи. Историю за прошлое оно не восстановит.
- Для нескольких объектов сразу есть парные методы `ВключитьВерсионированиеОбъектов`
  и `ВключеноВерсионированиеОбъектов`, они принимают список.

### 2. Встроить историю в форму объекта

**Задача:** на форме документа показать команду перехода к истории изменений.

**Функции:**

`ВерсионированиеОбъектов.ПриСозданииНаСервере(Форма) Экспорт` - процедура, регион
`ПрограммныйИнтерфейс`. Сервер.

**Пример:**

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

    ВерсионированиеОбъектов.ПриСозданииНаСервере(ЭтаФорма);

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Вызов идет в обработчике формы `ПриСозданииНаСервере`, а не в
  `ПриОткрытии`: элементы формы к моменту открытия уже должны быть на месте.
- Имя метода библиотеки совпадает с именем обработчика формы. Это не рекурсия:
  вызывается метод общего модуля, а не сама процедура формы.

### 3. Открыть историю изменений с клиента

**Задача:** по команде формы показать отчет об изменениях объекта.

**Функции:**

`ВерсионированиеОбъектовКлиент.ОткрытьОтчетПоИзменениям(Ссылка, АдресСериализованногоОбъекта) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. Тонкий и толстый клиент.

`ВерсионированиеОбъектовКлиент.ОткрытьОтчетПоВерсииОбъекта(Ссылка, АдресСериализованногоОбъекта) Экспорт`
- процедура, тот же регион.

**Пример:**

```bsl
&НаКлиенте
Процедура ИсторияИзменений(Команда)

    ВерсионированиеОбъектовКлиент.ОткрытьОтчетПоИзменениям(Объект.Ссылка, "");

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Не вызывать серверный `ВерсионированиеОбъектов` из клиентского обработчика:
  у него контексты сервера, толстого клиента и внешнего соединения, на тонком
  клиенте его нет. Для клиента есть парный модуль с суффиксом `Клиент`.
- Ссылка на новый, еще не записанный объект истории не имеет: команду для такого
  случая надо гасить.

### 4. Поправить поведение при восстановлении версии

**Задача:** при откате к прежней версии дозаполнить реквизиты, которых в старой
версии не было.

**Функции:**

`ВерсионированиеОбъектовПереопределяемый.ПриВосстановленииВерсииОбъекта(Объект, ДополнительныеРеквизиты) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. ХУК: библиотека вызывает его сама.

`ВерсионированиеОбъектовПереопределяемый.ПослеРазбораВерсииОбъекта(Ссылка, Результат) Экспорт`
- процедура, тот же регион и та же роль.

**Пример:**

```bsl
// Модуль ВерсионированиеОбъектовПереопределяемый, тело хука.
Процедура ПриВосстановленииВерсииОбъекта(Объект, ДополнительныеРеквизиты) Экспорт

    Если ТипЗнч(Объект) = Тип("ДокументОбъект.РасходТовара")
        И Не ЗначениеЗаполнено(Объект.Ответственный) Тогда
        Объект.Ответственный = Пользователи.ТекущийПользователь();
    КонецЕсли;

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Не вызывать `ВерсионированиеОбъектовПереопределяемый.ПриВосстановленииВерсииОбъекта(...)`
  из прикладного кода: это хук.
- Не записывать объект внутри хука: запись выполняет библиотека после его вызова,
  и своя запись даст лишнюю версию.

## Различия версий

Состав модулей и их экспортные методы в 3.1.11 и 3.2.1 совпадают - сверено по
обеим поставкам.

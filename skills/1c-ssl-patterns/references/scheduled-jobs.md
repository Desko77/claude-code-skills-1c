# Регламентные задания

Механизм БСП для заданий по расписанию: объявление собственного задания, поиск,
включение и выключение, чтение расписания и результата последнего выполнения.

Не путать с длительными операциями. Регламентное задание запускается ПЛАНИРОВЩИКОМ
по расписанию и работает без пользователя. Длительная операция запускается
действием пользователя и держит форму ожидания. Механизмы разные, модули разные.

## Модули механизма

| Модуль | Роль | Контексты |
|---|---|---|
| `РегламентныеЗаданияСервер` | программный интерфейс, его и вызывают | сервер, толстый клиент, внешнее соединение |
| `РегламентныеЗаданияПереопределяемый` | точка расширения: свои задания и расписания | сервер, толстый клиент, внешнее соединение |
| `РегламентныеЗаданияКлиент` | служебный, в прикладном коде не вызывается | тонкий и толстый клиент |
| `РегламентныеЗаданияСлужебный` | внутренняя реализация библиотеки | - |

**Модуля `РегламентныеЗадания` без суффикса не существует.** Имя выглядит
правдоподобно и в коде встречается как выдумка; программный интерфейс лежит
в `РегламентныеЗаданияСервер`.

**`РегламентныеЗаданияКлиент` объявлен целиком в регионе
`СлужебныйПрограммныйИнтерфейс`** - проверено по исходнику библиотеки. Клиентского
публичного интерфейса у механизма нет, и попытка позвать оттуда что-нибудь из
прикладного кода нарушает границу библиотеки.

## Сценарии

### 1. Объявить свое регламентное задание

**Задача:** добавить в конфигурацию задание, которое библиотека покажет в списке
настройки, а планировщик запустит по расписанию.

**Механизм:** объект метаданных `РегламентноеЗадание` создается в конфигурации, а
его описание для библиотеки заполняется в переопределяемом обработчике.

**Функции:**

`РегламентныеЗаданияПереопределяемый.ПриОпределенииНастроекРегламентныхЗаданий(Настройки) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. Это ХУК: библиотека вызывает его сама,
прикладной код только реализует тело. Вызывать по имени модуля нельзя.

**Параметры:**

- `Настройки` - `ТаблицаЗначений`, куда добавляется строка на каждое свое задание.
  Заполняются метаданные задания и, при необходимости, форма настройки и
  зависимости от функциональных опций.

**Пример:**

```bsl
// Модуль РегламентныеЗаданияПереопределяемый, тело хука.
Процедура ПриОпределенииНастроекРегламентныхЗаданий(Настройки) Экспорт

    Настройка = Настройки.Добавить();
    Настройка.МетаданныеЗадания = Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют;

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Не вызывать `РегламентныеЗаданияПереопределяемый.ПриОпределенииНастроекРегламентныхЗаданий(...)`
  из прикладного кода. Хук реализуют, а не зовут.
- Обработчик самого задания пишется в отдельном общем модуле и указывается в
  свойстве `ИмяМетода` объекта метаданных, а не в этом хуке.
- Второй метод модуля, `ПриОпределенииНастроек`, отвечает за общие настройки
  подсистемы, а не за перечень заданий. Имена похожи, назначение разное.

### 2. Найти задание по метаданным

**Задача:** получить объект задания, чтобы дальше включить его, выключить или
прочитать расписание.

**Функции:**

`РегламентныеЗаданияСервер.НайтиЗадания(Отбор) Экспорт` - функция, регион
`ПрограммныйИнтерфейс`. Сервер, толстый клиент, внешнее соединение.

**Параметры:**

- `Отбор` - `Структура` с полями отбора; чаще всего заполняется `Метаданные`.
- Возвращает `Массив` из `РегламентноеЗадание` в локальном режиме и
  `ТаблицаЗначений` в модели сервиса - это описано в шапке метода библиотеки.
  Код, рассчитанный только на массив, в модели сервиса сломается.

**Пример:**

```bsl
&НаСервере
Функция НайтиЗаданиеЗагрузкиКурсов()

    Отбор = Новый Структура;
    Отбор.Вставить("Метаданные", Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют);

    Задания = РегламентныеЗаданияСервер.НайтиЗадания(Отбор);
    Возврат ?(Задания.Количество() > 0, Задания[0], Неопределено);

КонецФункции
```

**Нюансы и антипаттерны:**

- Не обращаться к `РегламентныеЗадания.НайтиРегламентныеЗадания(...)` платформы
  напрямую: в модели сервиса заданий там нет, они лежат в очереди заданий.
  Функция библиотеки скрывает это различие.
- Пустой результат - штатный случай, а не ошибка: задание могло быть удалено из
  конфигурации при обновлении.

### 3. Включить или выключить задание из кода

**Задача:** погасить задание на время миграции данных и вернуть обратно.

**Функции:**

`РегламентныеЗаданияСервер.УстановитьИспользованиеРегламентногоЗадания(Знач Идентификатор, Знач Использование) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`.

`РегламентныеЗаданияСервер.РегламентноеЗаданиеИспользуется(Знач Идентификатор) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`.

**Параметры:**

- `Идентификатор` - метаданные задания, его уникальный идентификатор либо сам
  объект задания.
- `Использование` - `Булево`.

**Пример:**

```bsl
&НаСервере
Процедура ОстановитьЗагрузкуНаВремяМиграции()

    Задание = Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют;
    Если РегламентныеЗаданияСервер.РегламентноеЗаданиеИспользуется(Задание) Тогда
        РегламентныеЗаданияСервер.УстановитьИспользованиеРегламентногоЗадания(Задание, Ложь);
    КонецЕсли;

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Не менять свойство `Использование` у объекта задания напрямую с последующей
  записью: в модели сервиса это не даст эффекта, а библиотека не узнает об
  изменении.
- Выключение не прерывает уже запущенное задание. Оно лишь не будет запущено
  снова.

### 4. Прочитать и изменить расписание

**Задача:** показать пользователю текущее расписание и записать новое.

**Функции:**

`РегламентныеЗаданияСервер.РасписаниеРегламентногоЗадания(Знач Идентификатор, Знач ВСтруктуре = Ложь) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`.

`РегламентныеЗаданияСервер.УстановитьРасписаниеРегламентногоЗадания(Знач Идентификатор, Знач Расписание) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`.

`ОбщегоНазначенияКлиентСервер.РасписаниеВСтруктуру(Знач Расписание) Экспорт` и
`ОбщегоНазначенияКлиентСервер.СтруктураВРасписание(Знач РасписаниеСтруктурой) Экспорт`
- функции, регион `ПрограммныйИнтерфейс`. Доступны и на клиенте, и на сервере.

**Параметры:**

- `ВСтруктуре` - `Булево`. Истина возвращает расписание структурой, а не объектом
  `РасписаниеРегламентногоЗадания`.

**Пример:**

```bsl
&НаСервере
Процедура ПеренестиЗапускНаНочь()

    Задание = Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют;

    Расписание = РегламентныеЗаданияСервер.РасписаниеРегламентногоЗадания(Задание);
    Расписание.ВремяНачала = Дата(1, 1, 1, 3, 0, 0);

    РегламентныеЗаданияСервер.УстановитьРасписаниеРегламентногоЗадания(Задание, Расписание);

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Объект `РасписаниеРегламентногоЗадания` НЕ сериализуется и на клиент как есть не
  передается. Для передачи между клиентом и сервером его переводят в структуру
  парой `РасписаниеВСтруктуру` и `СтруктураВРасписание`; ключ `ВСтруктуре`
  делает то же самое на чтении.
- Расписание, полученное функцией, это копия. Правка копии ничего не меняет, пока
  не вызвана `УстановитьРасписаниеРегламентногоЗадания`.

### 5. Узнать, чем кончилось последнее выполнение

**Задача:** показать в интерфейсе, когда задание отработало и не упало ли.

**Функции:**

`РегламентныеЗаданияСервер.СвойстваПоследнегоЗадания(Знач Задание) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`.

**Пример:**

```bsl
&НаСервере
Функция СостояниеПоследнейЗагрузки()

    Задание = Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют;
    Свойства = РегламентныеЗаданияСервер.СвойстваПоследнегоЗадания(Задание);

    Если Свойства = Неопределено Тогда
        Возврат "Задание еще ни разу не выполнялось";
    КонецЕсли;

    Возврат Свойства.Состояние;

КонецФункции
```

**Нюансы и антипаттерны:**

- `Неопределено` при первом обращении - штатный случай, а не ошибка.
- Не разбирать журнал регистрации ради того же результата: функция библиотеки
  возвращает свойства фонового задания напрямую.

## Различия версий

- Модуль `ДополнительныеОтчетыИОбработкиРегламентныеЗаданияВМоделиСервиса` есть в
  библиотеке 3.1.11 и отсутствует в 3.2.1 - проверено по обеим поставкам. Код,
  ссылающийся на него, при переходе на 3.2.1 перестанет компилироваться.
- Состав `РегламентныеЗаданияСервер` и `РегламентныеЗаданияПереопределяемый` в
  этих версиях совпадает.

## Проверка перед использованием

Любой вызов из этого справочника проверяется до того, как попадет в код:

```bash
python skills/1c-bsp-api/scripts/bsp-api.py check РегламентныеЗаданияСервер.НайтиЗадания
```

Проверка сообщает и об устаревании вызова, а не только о его существовании.

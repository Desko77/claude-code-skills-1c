# Сервисы подписи: МЧД, DSS, мобильная подпись

Три механизма БСП вокруг электронной подписи, каждый со своим сервисом:
машиночитаемые доверенности ФНС, облачная криптография DSS, подписание через
мобильное устройство.

Основной механизм подписи описан отдельно; здесь только то, что добавляют
сервисы.

## Модули

| Модуль | Механизм | Контексты |
|---|---|---|
| `МашиночитаемыеДоверенности` | доверенности ФНС: формирование, подписание, регистрация, проверка | сервер, толстый клиент, внешнее соединение |
| `МашиночитаемыеДоверенностиФНСПереопределяемый` | точка расширения МЧД | сервер, толстый клиент, внешнее соединение |
| `СервисКриптографииDSS` и семейство из шести модулей | облачная криптография DSS | сервер / клиент |
| `СервисМобильнойПодписи`, `СервисМобильнойПодписиКлиентСервер` | подписание через мобильное устройство | сервер / общий |

**Имя модуля DSS не совпадает с названием подсистемы.** Подсистема называется
"Электронная подпись сервиса DSS", а модули начинаются с `СервисКриптографииDSS`.
Модуля `ЭлектроннаяПодписьDSS` в библиотеке НЕТ, проверено по обеим поставкам.

## Сценарии

### 1. Проверить доверенность подписанта

**Задача:** до приема подписанного документа убедиться, что доверенность
действует.

**Механизм:** модуль `МашиночитаемыеДоверенности`, регион `ПрограммныйИнтерфейс`.
Сервер. Формирование, подписание, регистрация в ФНС и проверка идут через него.

**Нюансы и антипаттерны:**

- Проверка обращается к внешнему сервису ФНС. Она сетевая, долгая и может быть
  недоступна: результат кэшируется библиотекой, а свой код обязан обрабатывать
  отказ сервиса.
- Доверенность привязана к сертификату подписанта. Действующая доверенность с
  чужим сертификатом документ не подтверждает.

### 2. Подписать через облачный сервис

**Задача:** у пользователя нет локального сертификата, ключ лежит в облаке.

**Механизм:** семейство `СервисКриптографииDSS`. Клиентская и серверная части
разделены, подтверждение операции интерактивное.

**Нюансы и антипаттерны:**

- Подписание через DSS все равно требует подтверждения ПОЛЬЗОВАТЕЛЕМ: серверный
  код не подпишет документ молча.
- Отдельный модуль подтверждения на клиенте существует именно потому, что
  операция асинхронная и с ожиданием ответа сервиса.

### 3. Подписать с мобильного устройства

**Задача:** руководитель подписывает документ телефоном.

**Механизм:** `СервисМобильнойПодписи` и его общая часть
`СервисМобильнойПодписиКлиентСервер`.

**Нюансы и антипаттерны:**

- Подпись приходит асинхронно и позже: документ остается неподписанным до ответа
  устройства, и интерфейс должен это показывать.
- Не считать вызов отправки подписанием: он лишь запрашивает подпись.

## Различия версий

Состав модулей всех трех механизмов в 3.1.11 и 3.2.1 совпадает - сверено по обеим
поставкам.

## Проверка перед использованием

Имена модулей здесь длинные и несовпадающие с названиями подсистем, поэтому
проверка особенно нужна:

```bash
python skills/1c-bsp-api/scripts/bsp-api.py modules СервисКриптографииDSS
```

# Контроль ведения учета и рассылка отчетов

Два механизма БСП, работающих в фоне и показывающих результат человеку: проверки
корректности данных с регистрацией найденных проблем и рассылка отчетов по
расписанию.

## Модули

| Модуль | Механизм | Контексты |
|---|---|---|
| `КонтрольВеденияУчета` | запуск проверок, регистрация проблем, отчет по ним | сервер, толстый клиент, внешнее соединение |
| `КонтрольВеденияУчетаПереопределяемый` | точка расширения: свои проверки | сервер, толстый клиент, внешнее соединение |
| `РассылкаОтчетов` | состав рассылки, получатели, формирование и отправка | сервер, толстый клиент, внешнее соединение |
| `РассылкаОтчетовПереопределяемый` | точка расширения рассылки | сервер, толстый клиент, внешнее соединение |

## Сценарии

### 1. Выполнить проверку данных

**Задача:** найти документы, нарушающие правило учета, и показать их
пользователю.

**Функции:**

`КонтрольВеденияУчета.ВыполнитьПроверку(Знач Проверка, Знач ПараметрыВыполненияПроверки = Неопределено, ПроверяемыеОбъекты = Неопределено) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. Сервер.

`КонтрольВеденияУчета.ВыполнитьПроверкиВКонтексте(КонтекстПроверокВеденияУчета) Экспорт`
- процедура, тот же регион.

`КонтрольВеденияУчета.ВидПроверки(Знач ПараметрыВыполненияПроверки, Знач ТолькоПоиск = Ложь) Экспорт`
и `КонтрольВеденияУчета.ВидыПроверок(ВидПроверок, ПоискПоТочномуСоответствию = Истина) Экспорт`
- функции, тот же регион.

**Нюансы и антипаттерны:**

- Не писать свой отчет о нарушениях: библиотека ведет регистр проблем,
  показывает их пользователю и снимает при исправлении.
- Проверка идет по расписанию либо по списку объектов. Полная проверка на большой
  базе долгая, и ее место в регламентном задании.
- Проблема снимается САМА при повторной проверке. Удалять запись вручную не надо.

### 2. Объявить свою проверку

**Задача:** правило учета, специфичное для конфигурации, должно проверяться
наравне с типовыми.

**Функции:**

Процедуры модуля `КонтрольВеденияУчетаПереопределяемый` - регион
`ПрограммныйИнтерфейс`. ХУКИ: библиотека вызывает их сама.

**Нюансы и антипаттерны:**

- Не вызывать процедуры переопределяемого модуля из прикладного кода: их
  реализуют.
- Проверка обязана быть повторяемой: она выполняется многократно, и каждый прогон
  должен давать один и тот же набор проблем на неизменных данных.

### 3. Выполнить рассылку отчетов

**Задача:** разослать отчет получателям по расписанию либо по команде.

**Функции:**

`РассылкаОтчетов.ВыполнитьРассылкуОтчетов(Рассылка, ПараметрыЖурнала = Неопределено, ДополнительныеНастройки = Неопределено) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`. Сервер.

`РассылкаОтчетов.ВыполнитьРассылку(Отчеты, ПараметрыДоставки, НаименованиеРассылки = "", ПараметрыЖурнала = Неопределено) Экспорт`
- функция, тот же регион: разовая рассылка без сохраненной настройки.

`РассылкаОтчетов.ВыполнитьРассылкиВФоновомЗадании(ПараметрыВыполнения, АдресРезультата) Экспорт`
- процедура, тот же регион.

**Нюансы и антипаттерны:**

- Формирование отчетов и отправка долгие. Из формы это делают фоновым заданием, а
  не синхронно.
- Две функции с похожими именами делают разное: одна работает по сохраненной
  настройке рассылки, другая по переданному списку отчетов. Перепутать легко.
- Ошибка доставки одному получателю не отменяет рассылку остальным. Результат
  разбирают по журналу, а не по факту возврата.

### 4. Добавить свой тип получателей

**Задача:** рассылать не только пользователям, но и своим контрагентам.

**Функции:**

`РассылкаОтчетов.ДобавитьЭлементВТаблицуТиповПолучателей(ТаблицаТипов, ДоступныеТипы, Настройки) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. Сервер. Вызывается из точки
расширения.

**Нюансы и антипаттерны:**

- Адреса получателей берутся из контактной информации. Свой тип должен уметь ее
  отдавать, иначе рассылка найдет получателей без адресов.

## Различия версий

Состав модулей обоих механизмов в 3.1.11 и 3.2.1 совпадает - сверено по обеим
поставкам.

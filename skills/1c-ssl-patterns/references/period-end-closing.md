# Даты запрета изменения

Механизм БСП, запрещающий править данные раньше указанной даты: закрытый период,
сданная отчетность, зафиксированные остатки. Запрет действует при записи объекта и
при загрузке данных из обмена.

## Модули механизма

| Модуль | Роль | Контексты |
|---|---|---|
| `ДатыЗапретаИзменения` | программный интерфейс: проверка запрета, обработчики подписок | сервер, толстый клиент, внешнее соединение |
| `ДатыЗапретаИзмененияПереопределяемый` | точка расширения: свои разделы запрета | сервер, толстый клиент, внешнее соединение |
| `ДатыЗапретаИзмененияСлужебный` и еще три с тем же суффиксом | внутренняя реализация библиотеки | - |

**Модуля `ДатыЗапрета` без слова `Изменения` не существует**, как и модуля
`ДатыЗапретаИзмененияКлиент`: публичного клиентского интерфейса у механизма нет.
Клиентские модули семейства служебные, все четыре.

## Сценарии

### 1. Проверить запрет перед своей операцией

**Задача:** до записи или до групповой обработки убедиться, что дата попадает в
разрешенный период, и показать понятную причину отказа.

**Функции:**

`ДатыЗапретаИзменения.ИзменениеЗапрещено(ДанныеИлиПолноеИмя, ИдентификаторДанных = Неопределено, ОписаниеОшибки = Null, УзелПроверкиЗапретаЗагрузки = Неопределено) Экспорт`
- функция, регион `ПрограммныйИнтерфейс`. Сервер.

`ДатыЗапретаИзменения.НайденЗапретИзмененияДанных(Знач ДанныеДляПроверки, ПараметрыСообщенияОЗапрете = Неопределено, ОписаниеОшибки = Null, УзелПроверкиЗапретаЗагрузки = Неопределено) Экспорт`
- функция, тот же регион. Отличается тем, что сама сообщает пользователю по
переданным параметрам сообщения.

`ДатыЗапретаИзменения.ПараметрыСообщенияОЗапрете() Экспорт` - функция-конструктор
структуры параметров, тот же регион.

**Пример:**

```bsl
&НаСервере
Функция ПериодОткрыт(Знач Ссылка)

    ОписаниеОшибки = "";
    Возврат Не ДатыЗапретаИзменения.ИзменениеЗапрещено(Ссылка, , ОписаниеОшибки);

КонецФункции
```

**Нюансы и антипаттерны:**

- Не сравнивать дату документа с константой даты запрета самостоятельно: запрет
  бывает разным по разделам, по организациям и по видам объектов, и одна дата все
  эти случаи не описывает.
- Параметр `ОписаниеОшибки` передается по ссылке и заполняется библиотекой -
  объявлять переменную нужно до вызова.

### 2. Подключить проверку к своему объекту

**Задача:** свой документ должен подчиняться датам запрета так же, как типовые.

**Механизм:** обработчики подписок на события. Они лежат в самом
`ДатыЗапретаИзменения` и вызываются подписками, а не прикладным кодом.

**Функции (обработчики подписок):**

`ПроверитьДатуЗапретаИзмененияПередЗаписью(Источник, Отказ) Экспорт`,
`ПроверитьДатуЗапретаИзмененияПередЗаписьюДокумента(Источник, Отказ, РежимЗаписи, РежимПроведения) Экспорт`,
`ПроверитьДатуЗапретаИзмененияПередЗаписьюНабораЗаписей(Источник, Отказ, Замещение) Экспорт`,
`ПроверитьДатуЗапретаИзмененияПередУдалением(Источник, Отказ) Экспорт`
- процедуры, регион `ПрограммныйИнтерфейс`. Для регистров бухгалтерии и расчета
есть отдельные обработчики с другой сигнатурой.

**Нюансы и антипаттерны:**

- Обработчик подбирается ПО ВИДУ объекта: у документа, у набора записей и у
  регистра расчета сигнатуры разные, и подписка с чужим обработчиком не
  скомпилируется.
- Не звать эти процедуры из модуля объекта напрямую: они рассчитаны на параметры
  подписки.
- Забытая подписка выглядит как работающий механизм: запрет просто не действует, и
  ошибки при этом нет.

### 3. Отключить проверку на время служебной операции

**Задача:** миграция или исправление данных должны пройти мимо запрета.

**Функции:**

`ДатыЗапретаИзменения.ОтключитьПроверкуДатЗапрета(Отключить) Экспорт` - процедура,
регион `ПрограммныйИнтерфейс`.

`ДатыЗапретаИзменения.ПроверкаДатЗапретаОтключена() Экспорт` - функция, тот же
регион.

**Пример:**

```bsl
&НаСервере
Процедура ИсправитьДанныеЗакрытогоПериода()

    ДатыЗапретаИзменения.ОтключитьПроверкуДатЗапрета(Истина);
    Попытка
        // служебная правка
        ДатыЗапретаИзменения.ОтключитьПроверкуДатЗапрета(Ложь);
    Исключение
        ДатыЗапретаИзменения.ОтключитьПроверкуДатЗапрета(Ложь);
        ВызватьИсключение;
    КонецПопытки;

КонецПроцедуры
```

**Нюансы и антипаттерны:**

- Включать проверку обратно обязательно, в том числе при исключении: отключение
  действует на сеанс, и забытый флаг снимает запрет для всей дальнейшей работы
  пользователя.
- Не оставлять отключение в коде, который выполняется по действию пользователя:
  это обход контроля, а не решение задачи.

### 4. Завести свой раздел запрета

**Задача:** запрет нужен не по организации, а по своему измерению - например по
складу.

**Функции:**

`ДатыЗапретаИзмененияПереопределяемый.ПриЗаполненииРазделовДатЗапретаИзменения(Разделы) Экспорт`
- процедура, регион `ПрограммныйИнтерфейс`. ХУК: библиотека вызывает его сама.

`ДатыЗапретаИзмененияПереопределяемый.ЗаполнитьИсточникиДанныхДляПроверкиЗапретаИзменения(ИсточникиДанных) Экспорт`
- процедура, тот же регион и та же роль: объявляет, откуда брать дату для проверки.

Имя первого хука длиннее, чем кажется: короткого `ПриЗаполненииРазделовДатЗапрета`
в библиотеке НЕТ, слово `Изменения` в конце обязательно.

**Нюансы и антипаттерны:**

- Не вызывать процедуры `ДатыЗапретаИзмененияПереопределяемый` из прикладного
  кода: их реализуют.
- Раздел, объявленный в хуке, должен иметь настройку в интерфейсе, иначе
  пользователь не сможет задать по нему дату.

## Различия версий

Состав модулей и их экспортные методы в 3.1.11 и 3.2.1 совпадают - сверено по
обеим поставкам.

# Руководство по семантической валидации для AI-ассистента

> **Версия:** 1.0  
> **Для:** AI-ассистенты работающие с Vanessa Automation  
> **Цель:** Предотвращение зацикливания и неправильного применения рекомендаций валидатора

---

## 🎯 Главное правило

**НИКОГДА не применяйте рекомендацию валидатора без семантической проверки!**

Высокая алгоритмическая схожесть (85%+) НЕ означает семантическую релевантность.

---

## 🔍 Обязательный чек-лист перед применением рекомендации

Для **каждой** рекомендации проверьте ВСЕ пункты:

```
☐ 1. Действие совпадает? (нажимаю vs ввожу vs выбираю)
☐ 2. Тип UI элемента совпадает? (кнопка vs гиперссылка vs поле)
☐ 3. Контекст совпадает? (в таблице vs в форме vs без контекста)
☐ 4. Параметры совместимы? (заголовок vs имя элемента)

Если ВСЕ ✅ → можно применять
Если хотя бы один ❌ → НЕ применять, спросить пользователя
```

## 📋 Детальные правила проверки

### 1. Проверка ДЕЙСТВИЯ

#### Категории действий

```yaml
Группа "Клик/Нажатие":
  - нажимаю
  - кликаю  
  - выбираю (на элемент)
  - щелкаю
  
  ✅ Взаимозаменяемы внутри группы
  ❌ НЕ заменяются на другие группы

Группа "Ввод данных":
  - ввожу
  - устанавливаю
  - задаю
  - заполняю
  
  ✅ Взаимозаменяемы внутри группы
  ❌ НЕ заменяются на другие группы

Группа "Выбор из списка":
  - выбираю из списка
  - выбираю из выпадающего списка
  - выбираю по строке
  - выбираю точное значение
  
  ✅ Взаимозаменяемы с учетом параметров
  ❌ НЕ заменяются на "Клик" или "Ввод"

Группа "Проверки":
  - проверяю
  - сравниваю
  - убеждаюсь
  - жду
  
  ✅ Взаимозаменяемы внутри группы

Группа "Навигация":
  - открываю
  - перехожу
  - закрываю
  - активизирую
  
  ⚠️ Каждое действие специфично, осторожно
```

#### Примеры проверки действия

```gherkin
# ✅ ПРАВИЛЬНО - действие совпадает
Оригинал:    "я нажимаю кнопку"
Рекомендация: "я нажимаю на кнопку"
Действие: нажимаю → нажимаю ✅
```

```gherkin
# ❌ НЕПРАВИЛЬНО - разные действия!
Оригинал:    "я ввожу в поле"
Рекомендация: "из выпадающего списка я выбираю"
Действие: ввожу → выбираю ❌

⚠️ Это РАЗНЫЕ действия! Тест будет работать некорректно!
→ НЕ применять, обратиться к пользователю
```

```gherkin
# ❌ НЕПРАВИЛЬНО - схожие слова, но разная семантика
Оригинал:    "я выбираю кнопку"  (клик)
Рекомендация: "я выбираю из списка"  (выбор значения)
Действие: выбираю (клик) → выбираю (из списка) ❌

⚠️ Слово одинаковое, но КОНТЕКСТ разный!
→ НЕ применять
```

### 2. Проверка ТИПА UI ЭЛЕМЕНТА

#### Иерархия элементов

```
Кнопочные элементы (взаимозаменяемы):
  ├─ кнопка
  ├─ кнопка с именем
  ├─ кнопка командного интерфейса
  └─ кнопка выбора

Поля ввода (взаимозаменяемы):
  ├─ поле
  ├─ поле с именем
  └─ поле ввода

Элементы выбора (НЕ взаимозаменяемы):
  ├─ выпадающий список
  ├─ список
  ├─ дерево
  └─ переключатель

Ссылочные элементы (НЕ взаимозаменяемы с кнопками!):
  ├─ гиперссылка
  └─ навигационная ссылка

Табличные элементы:
  ├─ таблица
  └─ табличная часть

Элементы форм:
  ├─ форма
  ├─ панель
  └─ группа
```

#### Примеры проверки элемента

```gherkin
# ✅ ПРАВИЛЬНО - элементы одной категории
Оригинал:    "нажимаю кнопку"
Рекомендация: "нажимаю на кнопку с именем"
Элемент: кнопка → кнопка с именем ✅
(разные селекторы, но тот же тип элемента)
```

```gherkin
# ❌ КРИТИЧЕСКАЯ ОШИБКА - разные типы элементов!
Оригинал:    "нажимаю на кнопку \"Создать\""
Рекомендация: "нажимаю на гиперссылку \"Создать\""
Элемент: кнопка → гиперссылка ❌

⚠️ Это РАЗНЫЕ элементы интерфейса!
Кнопка ≠ Гиперссылка
Схожесть 87% - ОБМАНЧИВА!

→ НЕ применять, обратиться к пользователю:
   "Валидатор предлагает заменить кнопку на гиперссылку.
    Это разные UI элементы. Что в вашем интерфейсе?
    1. Кнопка (обычная кнопка)
    2. Гиперссылка (текстовая ссылка)"
```

```gherkin
# ❌ НЕПРАВИЛЬНО - разные элементы ввода
Оригинал:    "в поле \"Наименование\" я ввожу"
Рекомендация: "из выпадающего списка \"Наименование\" я выбираю"
Элемент: поле → выпадающий список ❌

⚠️ Поле ввода и выпадающий список - РАЗНЫЕ элементы!
→ НЕ применять
```

```gherkin
# ⚠️ ОСТОРОЖНО - может быть ок, нужна проверка
Оригинал:    "в поле \"Покупатель\" я ввожу"
Рекомендация: "из выпадающего списка \"Покупатель\" я выбираю"

Анализ:
- В 1С поля с выбором могут работать и как поле ввода, и как список
- Но это РАЗНЫЙ способ заполнения

→ Обратиться к пользователю:
   "Поле 'Покупатель' в вашей форме:
    1. Поле ввода (можно набирать текст)
    2. Поле с выбором (нужно выбирать из списка)
    3. Комбинированное (можно и то, и другое)"
```

### 3. Проверка КОНТЕКСТА

#### Типы контекста

```yaml
Табличный контекст:
  - "в таблице \"Имя\""
  - "в табличной части \"Имя\""
  
  ✅ Взаимозаменяемы
  ❌ НЕ заменяются на контекст формы

Контекст формы:
  - "в форме"
  - без контекста (подразумевается форма)
  
  ✅ Часто взаимозаменяемы

Контекст дерева:
  - "в дереве \"Имя\""
  
  ❌ Специфичен, не заменяется

Отсутствие контекста:
  - Шаги без указания контекста
  
  ✅ Обычно работают везде
```

#### Примеры проверки контекста

```gherkin
# ✅ ПРАВИЛЬНО - контекст совпадает
Оригинал:    "в таблице \"Товары\" я нажимаю на кнопку"
Рекомендация: "в таблице \"ИмяТаблицы\" я нажимаю на кнопку"
Контекст: в таблице → в таблице ✅
```

```gherkin
# ❌ НЕПРАВИЛЬНО - разный контекст
Оригинал:    "в таблице \"Товары\" я активизирую поле"
Рекомендация: "я активизирую поле"  (контекст формы)
Контекст: в таблице → без контекста (форма) ❌

⚠️ Шаг для таблицы → шаг для формы
→ НЕ применять
```

```gherkin
# ⚠️ ВОЗМОЖНО ОК - нужна проверка
Оригинал:    "я нажимаю кнопку"  (без контекста)
Рекомендация: "в таблице \"Имя\" я нажимаю кнопку"
Контекст: без контекста → в таблице ⚠️

Анализ:
- Добавляется БОЛЕЕ специфичный контекст
- Может не подойти, если кнопка НЕ в таблице

→ Если в исходном сценарии НЕТ упоминания таблицы:
   НЕ применять, обратиться к пользователю
```

## 🚨 Антипаттерны (НИКОГДА не делайте так)

### Антипаттерн 1: Слепое применение первой рекомендации

```python
# ❌ НЕПРАВИЛЬНО
if error.suggestions:
    apply_first_suggestion(error.suggestions[0])
```

```python
# ✅ ПРАВИЛЬНО
if error.suggestions:
    for suggestion in error.suggestions:
        analysis = semantic_check(original=error.step, suggested=suggestion)
        if analysis.is_safe and analysis.confidence == "high":
            apply_with_explanation(suggestion, analysis)
            break
    else:
        # Ни одна рекомендация не подошла
        escalate_to_human(error)
```

---

### Антипаттерн 2: Игнорирование счетчика попыток

```python
# ❌ НЕПРАВИЛЬНО - ЗАЦИКЛИВАНИЕ!
while not validated:
    apply_fixes()  # бесконечный цикл
```

```python
# ✅ ПРАВИЛЬНО
MAX_ATTEMPTS = 3
attempt = 0

while not validated and attempt < MAX_ATTEMPTS:
    apply_fixes()
    attempt += 1

if attempt >= MAX_ATTEMPTS:
    escalate_to_human(reason="Max attempts reached")
```

## 🛡️ Защита от зацикливания - обязательный код (MAX_ATTEMPTS = 3)

### Шаблон для каждого AI-ассистента

```python
class ValidationLoop:
    MAX_ATTEMPTS = 3
    
    def __init__(self):
        self.attempt = 0
        self.history = []
    
    def validate_and_fix(self, scenario_file):
        while self.attempt < self.MAX_ATTEMPTS:
            result = run_validator(scenario_file)
            
            if result.is_valid:
                return SUCCESS
            
            # Применяем исправления
            applied_fixes = self.apply_semantic_fixes(result.errors)
            
            if not applied_fixes:
                # Не смогли применить ни одного исправления
                self.escalate_to_human(
                    reason="No applicable fixes found",
                    errors=result.errors
                )
                return ESCALATED
            
            self.history.append({
                "attempt": self.attempt,
                "errors": result.errors,
                "fixes": applied_fixes
            })
            
            self.attempt += 1
        
        # Зациклились
        self.escalate_to_human(
            reason="Maximum attempts reached",
            errors=result.errors,
            history=self.history
        )
        return ESCALATED
```

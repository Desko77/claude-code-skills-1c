# Claude Code Skills for 1C:Enterprise

Набор скилов, правил и команд для [Claude Code](https://docs.anthropic.com/en/docs/claude-code), ориентированных на разработку 1С:Предприятие.

**Версия 1.0.** **112 скилов** для работы с конфигурациями, расширениями, обработками, формами, макетами, запросами, ролями, подсистемами, пакетами XDTO, базами данных, веб-публикацией и веб-тестированием 1С, а также разработкой под 1С 7.7, правилами обмена «Конвертация данных» и интеграцией с Mobile SMARTS (Клеверенс).

Отдельный класс - справочники API прикладных конфигураций (см. раздел «Справочные и утилитарные»). Первый такой скил - `zup-hr-api-reference` для 1С:ЗУП 3.1.

**29 правил** - стандарты кода BSL, антипаттерны, оптимизация запросов, паттерны расширений, генерация форм, требования EDT, БСП API и переиспользование БСП, права ролей, прямой запрос в отчётах, безопасная запись BSL-модулей, Python-first интеграции, двухпроходный СКД, верификация работы агента, тестирование, ревью, выбор моделей, SDD-workflow.

## Установка

### Через скил (рекомендуется на уже настроенной машине)

Скил `claude-env-setup` ставит набор и связанные инструменты, не ломая то, что уже работает:
сначала снимает опись машины, показывает план, ставит ТОЛЬКО выбранное, конфиги MCP правит
слиянием, а расходящиеся файлы не перезаписывает молча, а показывает diff. Годится и для
чистой машины, и для дозагрузки недостающего.

Готовые промпты, которые можно скопировать и отдать агенту (первая установка, обновление,
проверка без установки, установка одного компонента) - в
[`skills/claude-env-setup/PROMPT.md`](skills/claude-env-setup/PROMPT.md).

### Вручную

> На машине, где вы уже дорабатывали скилы под себя, команды ниже затрут ваши правки.
> Там безопаснее пофайловая установка через скил выше.

#### Скилы

Скопировать папку `skills/` в `~/.claude/skills/`:

```bash
# Весь набор
cp -r skills/* ~/.claude/skills/

# Или конкретные скилы
cp -r skills/1c-meta-compile ~/.claude/skills/
```

#### Правила

Скопировать файлы из `rules/` в `~/.claude/rules/`:

```bash
cp rules/*.md ~/.claude/rules/
```

#### Команды

Скопировать файлы из `commands/` в `~/.claude/commands/`:

```bash
cp commands/* ~/.claude/commands/
```

Скилы спроектированы по слоям — базовые (генерация XML) работают без платформы, продвинутые требуют 1С или MCP.

### MCP-серверы, на которые ссылаются скилы

Сами серверы в этот репозиторий не входят - они ставятся и настраиваются отдельно, в `.mcp.json`
проекта или в пользовательских настройках Claude Code. Здесь перечислены ключи ровно в том виде, в
каком они пишутся в скилах и правилах, чтобы ссылки читались однозначно.

| Ключ сервера | Для чего | Кто использует |
|--------------|----------|----------------|
| `ai-edt` | BSL-код, метаданные, формы, валидация запросов, ошибки проекта, отладка, обновление ИБ в EDT-проекте. Плагин **AI-EDT** (`ru.aiedt.mcp.server`), 118 инструментов в фасадах | `ai-edt-tools`, `composing-1c-queries`, `1c-query-optimization` |
| `bsl-platform-help` | API платформы: методы, типы, сигнатуры, конструкторы, стиль и строгая типизация | `1c-platform-docs` |
| `1c-naparnik` | Ревью кода, стандарты ИТС, документация платформы и конфигураций | `1c-naparnik` |
| `1c-mcp_ssl_server` | Поиск функций БСП по описанию задачи | `1c-ssl-patterns` |
| `1c-forms-mcp` | Генерация обычных (неуправляемых) форм вне EDT-проекта | правило `forms_generation.md` |
| `1c77-metadata` | Конфигурация 1С 7.7: объекты, реквизиты, модули ([установка](https://github.com/ivanarama/77MCP)) | `1c77-dev` |
| `1c-syntax-checker-mcp` | Проверка синтаксиса BSL без запущенной EDT | правило `mcp-tool-priority.md` |
| `1c-templates-mcp` | Поиск и хранение шаблонов кода | правило `mcp-tool-priority.md` |

Под EDT существуют разные MCP-плагины. Скил `ai-edt-tools` и правила написаны под **AI-EDT**: ключ
`ai-edt`, инструменты свернуты в фасады с маршрутизацией `operation=`. Если подключен другой плагин -
например [DitriXNew/EDT-MCP](https://github.com/DitriXNew/EDT-MCP) (там ключ `EDT MCP Server`, 87
инструментов, фасадов нет) - каталог из `references/` к нему не применим: бери фактические имена из
`tools/list` и документацию своего плагина.

Отдельно: `1c-mcp-toolkit` - это скил репозитория, а не MCP-сервер. Он ходит в живую базу по HTTP через
обработку `MCP_Toolkit.epf`, поэтому в `.mcp.json` его прописывать не нужно.

### Справочные и утилитарные

**Справочники API прикладных конфигураций 1С** - отдельный класс скилов, рассчитанный на объёмные тематические справочники (методы, поля, паттерны конфигурации), которые дорого держать в глобальном контексте. Устройство: полный текст справочника лежит в `references/` внутри папки скила, а SKILL.md содержит только короткое описание-триггер (~150 токенов). Модель подтягивает справочник через Read **только когда видит, что задача касается этой конфигурации** - остальное время он не потребляет контекст. Паттерн легко расширяется: `erp-api-reference`, `ut-api-reference`, `buh-api-reference` и т.п. делаются по той же схеме - собрать API-справочник в `references/имя-справочника.md` и написать SKILL.md с точным описанием-триггером.

Для фиксированной привязки к конкретному проекту (всегда грузить, без опоры на триггер) в CLAUDE.md проекта можно добавить `@~/.claude/skills/<skill>/references/<file>.md`.

## Регресс-тесты скилов

Скрипты скилов покрыты снапшот-тестами: скил получает вход, генерирует файлы, результат сравнивается
с эталоном. Быстро, файлово, без платформы 1С.

```bash
node tests/skills/runner.mjs                       # весь набор
node tests/skills/runner.mjs cases/1c-meta-compile # один скил
node tests/skills/runner.mjs --update-snapshots    # перегенерировать эталоны
node tests/skills/runner.mjs --runtime python      # прогнать python-версии скриптов
```

Требуется Node.js 18+. Текущее состояние: **452 зеленых из 761**, 46 пропущено по условиям среды.
Остальные 263 - реестр незакрытой функциональности `tests/skills/known-gaps.json`: скрипт не знает
типа объекта, операции или параметра, которые поддерживает исходный набор. Раннер использует реестр
как гейт - падение ИЗ реестра ожидаемо, падение ВНЕ его означает регресс и роняет прогон. Подробности
и порядок работы с реестром - `tests/skills/README.md`.

## Хуки (экспериментально, по умолчанию выключены)

В каталоге `hooks/` два хука Claude Code, дополняющие проверки, встроенные в сами скилы:

- **support-guard** - блокирует прямую правку через `Edit`/`Write` объекта типовой конфигурации,
  стоящего на поддержке поставщика, и в отказе говорит, что делать вместо этого.
- **skill-suggester** - при ручной работе с исходниками 1С напоминает про профильный скил: при
  чтении ведет на `*-info`, при правке - на мутатор. Не блокирует, срабатывает не чаще раза за
  сессию на группу.

Требуется Node.js 18+. Автоматически не подключаются: порядок ручного включения и настройки - в
`hooks/README.md`.

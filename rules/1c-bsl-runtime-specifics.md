# Особенности выполнения BSL, которые не видит статический анализ

Применяется: при написании и ревью кода BSL. Описанные ошибки проходят валидацию EDT и проявляются
только при выполнении.

Транзакции и управляемые блокировки - `1c-transactions-and-locks.md`, каталог дефектов -
`anti_patterns.md`.

---

## Коллекции и типы

- **`Объект.ДополнительныеСвойства` - `Структура`, а не `Соответствие`**: `.Свойство("Ключ")`, а не
  `.Получить()` (ошибка выполнения).
- **`ПрочитатьJSON(Чтение, Истина)` возвращает `Соответствие`** (метода `.Свойство` нет), без флага -
  `Структура`. У `ОбщегоНазначения.JSONВЗначение` второй параметр - `ИменаСвойствСоЗначениямиДата`,
  третий - `ПрочитатьВСоответствие`.
- **`.Выгрузить()` и `.Скопировать()`**: поле строки `Выгрузить()[0]`, соответствующее вложенной
  табличной части (`Таблица.(...) КАК ВложеннаяТЧ`), - `ТаблицаЗначений`: у него есть `.Скопировать()`
  и нет `.Выгрузить()`. Ошибка "Метод не обнаружен" при выполнении; статический анализ ее не находит,
  потому что тип поля произвольный.
- **У `ДокументОбъект` и строки табличной части нет метода `.Свойство()`** - он есть у `Структура`,
  `ФиксированнаяСтруктура`, `ДанныеФормыСтруктура`.
- **`Для X = 5 По 0` выполняет ноль итераций** (счетчик только возрастает) - обратный обход через
  `Пока Индекс >= 0`.
- **Нет динамического вызова `Модуль[ИмяМетода](Параметры)`** - явный `Если / ИначеЕсли`.
  `Вычислить()` и `Выполнить()` медленны и небезопасны.

## Режимы и блокировки

- **`УстановитьПривилегированныйРежим(Ложь)` без парного `(Истина)` в той же процедуре завершается
  ошибкой** (счетчик ведется по процедуре), и ошибка маскируется в `Исключение`. Восстанавливать режим
  по сохраненному флагу. `ПривилегированныйРежим()` возвращает состояние всего стека вызовов, для
  этой проверки не подходит.
- **`УстановитьВремяОжиданияБлокировкиДанных()` - административный метод** (монопольный доступ к ИБ,
  сеанс без разделителей), а не таймаут конкретной управляемой блокировки. Из прикладного кода дает
  "База заблокирована". Управляемые блокировки ждут глобальный таймаут сами.
- **Управляемую блокировку документа или справочника ставить только по `Ссылка`**: реквизиты, включая
  `Номер`, в пространстве блокировок недоступны. Защита от дублей при параллельном создании по
  бизнес-ключу - блокировка по значению измерения регистра-семафора (запись в регистр не нужна).

## Параметры и результаты вызовов

- **`?(Условие, Отказ, Неопределено)` в параметре передает переменную `Отказ` по ссылке.**
  `ОбщегоНазначенияКлиентСервер.СообщитьПользователю(Текст, , , , ?(РежимЗаписи = РежимЗаписиДокумента.Проведение, Отказ, Неопределено))`
  устанавливает `Отказ = Истина` в вызывающей процедуре; при ложном условии переменная не меняется.
  Такой вызов - рабочий отказ записи, а не сообщение без отказа.
- **Типовые методы записи в модулях менеджеров перехватывают исключения** (`Попытка` ->
  `ОтменитьТранзакцию` -> журнал регистрации -> `Ложь`), и вызывающий код считает запись выполненной.
  Для пакетной записи - `СоздатьНаборЗаписей()`, `Отбор`, `Записать()` напрямую и проверка
  возвращаемого значения.
- **Мультиязычность ERP**: `Наименование` и `НаименованиеЯзыкN`; перед записью -
  `МультиязычностьСервер.ПередЗаписьюНаСервере(Объект)`.

## Хранение настроек и версии подсистем

- **Справочник-контейнер настроек вместо множества констант**: реквизит `Значение` составного типа и
  функция модуля менеджера `Получить("Имя1,Имя2")` (одно имя - значение, список - `Структура`,
  привилегированный режим, отсутствующее имя - `Неопределено`). Булеву настройку сравнивать
  `= Истина`: `Если Настройка Тогда` завершается ошибкой на `Неопределено` у составного типа.
- **Версию подсистемы поднимать только вместе с обработчиком обновления.** Начальное заполнение
  выполняется один раз на новых базах; для уже обновленных баз нужен новый обработчик на следующей
  версии.

## ЗУП 3.x

- **Дубль в регистре сведений при подмене измерения без свертки** дает "запись с ключом уже
  существует" и откат (регистры накопления дубли суммируют, регистры сведений - отказывают). Исправление:
  `СГРУППИРОВАТЬ ПО` ключу с агрегатом. Замена по физическим лицам - через
  `Соответствие[ФизЛицо -> Структура]` и обход строк табличной части.
- **Документ с `ПериодРегистрации < МесяцНачисления` должен создавать исправление, а не
  перезаписывать документ**: документ прошлого периода включает уволенного и отказывает на дате запрета
  (дата запрета - защита, а не причина). "Расчет переплаты" закрывает `ЗарплатаКВыплате` приходом с
  отрицательными суммами, поэтому проверка только расхода его не видит. Закрытие определяется по типу
  регистратора.
- **Виды межрасчетных выплат - составной тип `EnumRef + String(60)`** (часть значений - строки из
  функций-оберток), сравнение - через вызов функции. Строка длиннее `String(N)` обрезается без ошибки,
  и запрос отказывает "Ожидается ВЫБРАТЬ".
- **`КадровыйУчет.СоздатьВТРабочиеМестаСотрудников`** вместо прямого обращения к
  `ТекущиеКадровыеДанные` и `ЗанятостьПозиций`: учитывает уволенных, подработки, договоры ГПХ.
  Отбор уволенных - `КадровыйУчет.КадровыеДанныеСотрудников(..., "ДатаУвольнения")`. Дни за счет
  работодателя по 255-ФЗ: обычная болезнь и НСПЗ - 3 дня, БиР и уход - 0.
- **Запись без проверки даты запрета (`ОбменДанными.Загрузка = Истина`,
  `ЗарплатаКадры.ОтключитьБизнесЛогикуПриЗаписи`) - только в тестовых скриптах**, в рабочей базе -
  типовые документы.
- **Групповое формирование статистической отчетности (П-4) выполняет свою постобработку** и может
  расходиться с отчетом, сформированным вручную, - сверять. `ДанныеОтчета` регламентированного
  отчета - `ХранилищеЗначения` (ячейки "П" + код, тысячи; разделы - рубли).

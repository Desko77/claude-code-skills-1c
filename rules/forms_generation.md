# Генерация и модификация форм 1С

Основной путь - EDT MCP (`1c-edt`). Сервер `1c-forms-mcp` в этом стеке отключен: на EDT-проектах он генерирует формы хуже и с ошибками. Использовать только как fallback для конфигураций без EDT (формат Конфигуратора), предварительно включив сервер вручную.

## Формы в EDT-проекте (Form.form) - через EDT MCP

Файл формы в EDT - `Form.form` (не `Form.xml`). Работать инструментами `1c-edt` (см. скил `1c-edt-tools`, `references/metadata-forms-constructors.md`).

### Создание формы

1. `edit_metadata operation=create_form` (`createForm`) - создает форму с базовыми свойствами (иначе форма не открывается). Для `CommonForm` автоматически создается форма-обертка.
2. `edit_metadata` form-операции - наполнение: `addField`, `addGroup`, `addButton`, `addTable`, `addDecoration`, командный интерфейс, события формы.
3. `get_form_structure` - проверить дерево элементов (JSON), `includeCommandInterface=true` для командного интерфейса.
4. `get_form_screenshot` - визуальный контроль (PNG из WYSIWYG), параметр `activePage` для страниц.
5. Валидация результата строго по порядку: `revalidate_objects` по форме и владельцу, затем `get_project_errors` с фильтром по ним (без перевалидации ошибки останутся от прошлого состояния).

### Модификация формы

1. `get_form_structure` - обзор текущих элементов.
2. `get_form_screenshot` - текущее состояние.
3. `edit_form` / `edit_metadata` form-операции - добавить (`addField`/`addGroup`/`addButton`/`addTable`) или удалить (`removeItem`) элементы.
4. `get_form_screenshot refresh=true` - проверить результат.

Требования к XML `Form.form` (extInfo, дефолты полей, привязка handlers) - `edt-form-xml-requirements.md`.

### Именование form-команд и кнопок (конвенция EDT)

Именовать form-команду ПО ДЕЙСТВИЮ, чисто, без машинных суффиксов:
- команда: `ПечатьСкладскихНакладных` (НЕ `ПечатьСкладскихНакладныхCommand`);
- обработчик команды: то же имя `ПечатьСкладскихНакладных` (НЕ `...Команда`);
- кнопка: `add_button name=ПечатьСкладскихНакладных` - плагин 3.1.x сам создаёт одноимённую команду (item и command в разных пространствах имён, одноимённость допустима). Раньше плагин клеил `<name>Command` / `<commandName>Команда` - устарело, не воспроизводить вручную.

Так делает сам EDT (стоковая форма: команда `ПереключитьАктивностьПроводок`, обработчик `ПереключитьАктивностьПроводок`; кнопку EDT-мастер именует `Форма<Команда>`). `add_form_command` вернёт `warning`, если передать `commandName` с суффиксом `Command`/`Команда`.

## Fallback: формат Конфигуратора (без EDT)

Если проект НЕ в EDT и нужен формат Конфигуратора (`logform`) или упрощенный (`managed`), существует MCP-сервер `1c-forms-mcp` (по умолчанию отключен в этом стеке). Включить вручную в конфиге и использовать его тулзы (`get_form_prompt`, `generate_form`, `validate_form`, `convert_form`). На EDT-проектах НЕ применять - EDT MCP точнее и не делает ошибок в форме.

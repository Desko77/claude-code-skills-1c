# Особенности запросов 1С

Применяется: при написании и правке текстов запросов - в модулях, в схемах СКД, в запросах к живой
базе.

Синтаксис, виртуальные таблицы и их параметры - скил `composing-1c-queries`, оптимизация -
`query-optimization-tips.md`.

---

## Совместимость типов и пакеты

- **Конфигуратор проверяет `ОБЪЕДИНИТЬ` со строками строже, чем `validate_query`**: запрос проходит
  `validate_query` без ошибок, а Конфигуратор отказывает "Несовместимые типы". Ссылки выбирать
  напрямую (не `ПРЕДСТАВЛЕНИЕ`), пустые значения - `NULL` (не `""`), строку - только в одной ветке,
  признаки - булевы значения или ссылки на перечисление.
- **Пакет через `ВыполнитьПакет()`: псевдонимы полей в каждом `ВЫБРАТЬ`.**
- **Запрос к документам основной конфигурации валидировать в проекте основной конфигурации**, а не
  проекта расширения: в проекте расширения `validate_query` дает ложные "поле не найдено".

## Соединения

- **`ПОЛНОЕ СОЕДИНЕНИЕ` двух временных таблиц N x M по ключу дает декартово произведение**
  (`РАЗЛИЧНЫЕ` не помогает при разных полях) - `СГРУППИРОВАТЬ ПО` ключу с агрегатом.
- **Поиск расхождений значений**: `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` с условием `ГДЕ Поле <> Актуальное` вместо
  `ЛЕВОЕ СОЕДИНЕНИЕ` с `ЕСТЬ NULL`, когда сравниваются значения, а не наличие записи.

## Регистр бухгалтерии с корреспонденцией (Хозрасчетный)

- В физической таблице нет полей `Счет` и `Субконто1` - только `СчетДт` / `СчетКт`; субконто есть
  только в `ОборотыДтКт` и `ДвиженияССубконто`.
- В параметре условия по счету `ОборотыДтКт` нельзя `СчетДт.Код В (...)` - только подзапрос к плану
  счетов.
- Условие `Организация = &Организация` в параметрах виртуальной таблицы регистра часто не
  срабатывает - `ДвиженияССубконто` (условие в 3-м параметре) или подзапрос через физическую таблицу.

## Приемы

- **Выполнение в три фазы (SQL -> BSL -> SQL)** через `МенеджерВременныхТаблиц`, когда часть данных
  получается только методами BSL.
- **Шаблон запроса к регистру**: реальный регистр-эталон и `ПодставитьПараметрыРегистраВЗапрос()`
  вместо подстановки `{...}` в текст.
- **Постраничная выборка по ключу** (`ПЕРВЫЕ N ... ГДЕ Ссылка > &Последняя УПОРЯДОЧИТЬ ПО Ссылка`)
  эффективнее пропуска N записей.
- **Пустая строка в строковом литерале текста запроса в BSL - `""""`** (четыре кавычки), а не `""`:
  пара `""` внутри литерала BSL - это одна экранированная кавычка, текст запроса сдвигается,
  следующий `КАК` попадает в строку, и запрос отказывает "поле объекта не обнаружено (Псевдоним)".

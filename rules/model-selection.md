# Стратегия выбора моделей

Распределение моделей по ролям.

Применяется: при работе с AI-ассистентами (Claude Code, Cursor, другие IDE).

---

## Принцип

**Opus — основная рабочая модель оркестратора. Кросс-ревью — внешние модели (Codex gpt-5.6-sol / Cursor Grok), Sonnet отключён. Субагенты-исполнители — по типу их работы (Haiku / Sonnet / Opus).**

Основная сессия (оркестратор - тот, кто держит замысел и принимает решения): анализ, кодогенерация, рассуждение, рефакторинг - Opus. Кросс-ревью (план, код) с 2026-07-15 делают внешние модели через подписки, экономя Claude-токены: основной ревьюер - Codex gpt-5.6-sol (нативный `codex review`), опционально Grok через Cursor; Sonnet из ревью отключен (детали и fallback - в промптах кросс-ревью). Субагентам, которым делегируется ИЗОЛИРОВАННАЯ работа (разведка, механическая выборка, отдельный анализ), модель подбирается по типу задачи - от Haiku на механике до Opus на тяжелом анализе (см. «Модель субагента по типу задачи»).

**Третий уровень - Fable 5 (claude-fable-5)** точечно поверх Opus на long-horizon автономных прогонах и самых тяжелых задачах (см. раздел ниже). Не дефолт: дороже Opus вдвое и быстрее расходует недельную квоту, включается под конкретный заход через `/model`.

## Распределение

### Opus — все задачи

| Категория | Примеры |
|-----------|---------|
| **Архитектура** | Проектирование, выбор технологий, breaking changes, миграция |
| **Безопасность** | Ревью кода, аудит RLS, поиск уязвимостей |
| **Production-баги** | Порча данных, race conditions, регрессии |
| **Кодогенерация** | Формы, тесты, запросы, скрипты, конфигурации |
| **Рефакторинг** | Упрощение, извлечение методов, консолидация |
| **Исследование** | Навигация по коду, поиск, документация |
| **Итеративная работа** | Баг-фиксы, реализация фич, тестирование |

### Кросс-ревью — внешние модели (Codex / Grok), не Sonnet

| Когда | Кто ревьюит |
|-------|-----------|
| После завершения кода | Codex gpt-5.6-sol (`codex review`, сам читает git diff) + опц. Grok через Cursor |
| После составления плана | Codex gpt-5.6-sol (нативный `codex review`) + опц. Grok |

С 2026-07-15 кросс-ревью ушло на внешние подписки (Codex ChatGPT - лимиты по времени, дешевле частого
ревью; Cursor - Grok). Экономит Claude-токены. Sonnet из ревью отключён (fallback-схема Opus↔Sonnet - в
отдельный набор промптов кросс-ревью). Механика - скилы для внешних моделей.

### Fable 5 (claude-fable-5) - точечно, поверх Opus

Самая мощная модель Anthropic, под long-horizon автономную работу и самые тяжелые рассуждения. Дороже Opus 4.8 вдвое ($10/$50 против $5/$25 за 1M токенов), быстрее расходует недельную квоту. Не дефолт - включать под конкретный заход.

**Кто инициирует.** Агент сам Fable НЕ включает: основную модель сессии не переключает вообще (только пользователь через `/model`), субагента на `fable` молча не поднимает. Когда задача попадает в профиль ниже - агент ПРЕДЛАГАЕТ переключиться (`/model`) или поднять субагента на Fable; решение за пользователем. Кросс-ревью (Codex/Grok) агент запускает сам по правилу.

**Брать Fable 5 вместо Opus 4.8:**

| Задача | Пример из проектов |
|--------|--------------------|
| Длинные автономные прогоны (overnight, без коррекции) | Миграция 7.7-УНФ (цикл сборка-деплой-toolkit-тест-фиксы, потоки A-G); марафоны EDT-MCP (build-install-live-verify) |
| First-shot реализация по четкому ТЗ | Обмены КД 2.0/3.1 - резать число итераций (v7..v19) |
| Параллельные долгоживущие суб-агенты | Потоки A-G миграции, параллельные исследования SDD |
| Глубокий root-cause через несколько конфигураций | Баги УХ+БП (ОКА-задачи, трассировка контрактов) |
| Enterprise deliverables | Бюджетирование УХ, xlsx-отчеты по изменениям, docx-инструкции |
| Vision на плотных/деградированных картинках | Скриншоты форм EDT, сканы накладных |

**Оставить Opus 4.8 / Sonnet:**

- **Security** (`audit_role_rights`, `find_rls_violations`, `sensitive_data_scan`) - прибавка Fable в поиске багов на security-анализ НЕ распространяется + риск ложного `refusal` (включены cyber-классификаторы).
- **Рутина**: единичные правки, простые баг-фиксы, опечатки - избыточно и вдвое дороже.
- **Кросс-ревью** - внешние модели (Codex gpt-5.6-sol / Grok через подписки), не Fable и не Sonnet.
- **Интерактив с быстрым откликом** - turns Fable идут минутами; fast mode на Fable НЕТ (только Opus 4.8/4.7).

**Ограничения:** требует 30-дневного хранения данных (не работает через ZDR). Промо до 07.07.2026: до 50% недельного лимита на Fable, дальше платные кредиты - использовать прицельно на 1-2 крупных задачах, не размазывать по мелочи.

### Модель субагента по типу задачи

Субагент наследует модель родителя по умолчанию; при делегировании через Agent/Task задавать `model` явно ПО ТИПУ работы субагента, а не по абстрактной «сложности» (тип воспроизводим, сложность на глаз плавает).

| Тип работы субагента | Модель | Примеры |
|----------------------|--------|---------|
| Механическая изоляция ВНЕ BSL/1С | **Haiku** | список файлов, греп по тексту/логам, суммаризация документов и выгрузок по жесткому формату, дамп не-кода по четкому ТЗ |
| Разведка 1С/BSL и интерпретация | **Sonnet** | ЛЮБАЯ BSL-разведка (выгрузка структуры модуля `get_module_structure`, `find_references`, трассировка «как работает X», сопоставление зависимостей) |
| Тяжелый анализ / изолированная реализация | **Opus** | архитектурный разбор, security-аудит (RLS/права/чувствительные данные), сложная многошаговая правка в изоляции |

- **BSL/1С-разведка - НИКОГДА не Haiku, только Sonnet или Opus.** Любое обращение к 1С-коду или метаданным - трассировка, «как работает X», и даже механическая выгрузка структуры модуля/метаданных под последующий анализ - отдавать минимум Sonnet. Haiku слабее в понимании кода, а дженерик-субагент (Explore) и так не 1С-осведомлен: неточная выжимка отравляет выводы оркестратора (он ей доверяет). Haiku остается только на механику ВНЕ кода (файловые списки, греп по тексту/логам, суммаризация документов по формату).
- **Оркестратор остается Opus.** Мельчить оркестратора на Haiku/Sonnet нельзя - он держит замысел и принимает решения; экономия только на изолированных субагентах-исполнителях.
- **Security - всегда Opus** (и в субагенте): прибавки дешевых моделей на аудит прав/RLS/чувствительных данных нет, цена пропуска нарушения выше экономии.
- Как задать: `Agent`/`Task` с `model: "haiku"|"sonnet"|"opus"`. Тип субагента может нести модель по умолчанию в своем определении - явный `model` в вызове ее переопределяет.

## Поведение на Opus 5

Раздел про то, как ведет себя работающая модель, а не про выбор модели под задачу. Длина ответов,
дисциплина коррекций и границы объема работ уже заданы средой Claude Code, здесь только то, чего в ней
нет.

- **Проверку собственной работы субагенту не поручать.** Модель охотно делегирует, и на своем же диффе
  это дает второй проход без нового знания: субагент видит то же, что и родитель, и подтверждает его
  выводы. Проверка чужой работы субагентом - другое дело и остается в силе.
- **Ревью запрашивать с полным покрытием, фильтровать в отчете.** Формулировка вида "только критичное"
  на этой модели дает не лучший фильтр, а меньше находок: она понимает планку буквально и часть
  дефектов не называет вовсе. Просить все находки с уровнем серьезности, а отбор делать при подаче
  результата пользователю.
- **Уровень усилий подбирать под тип задачи.** Полный цикл по нескольким модулям, архитектура, правка
  метаданных и тяжелая диагностика - высокий; правка документации, разбор одного сообщения об ошибке и
  справочные вопросы - низкий и средний, на этой модели они справляются.
- **Инструментальные проверки, предписанные правилами, самопроверкой не считаются.** Валидаторы,
  прогон тестов и перевалидация объектов остаются обязательными в полном объеме независимо от того, как
  настроено поведение модели.

## Принципы экономии контекста

### Инкрементальная загрузка

Вместо чтения целого файла — читать нужный фрагмент (сигнатуру, метод). Расширять при необходимости.

### Изоляция через агентов

Параллельные задачи запускать через агентов — каждый со своим контекстом. В основной чат возвращается только результат.

Особый мотив для MCP: результаты MCP-вызовов копятся в контексте родителя до `/compact`. Тяжелые выборки (широкий поиск по коду, `find_references`, `ai_context depth=full`, объемные `recall`/`its_help`) уводить в субагента - сырье остается в его контексте, в родителя приходит выжимка. Субагент наследует и глобальные, и project-scoped MCP родителя (EDT MCP `ai-edt` подтвержден 2026-07-07 на `general-purpose` живыми вызовами). Нюансы (Explore/Plan с урезанным tools-списком, EDT должна быть запущена для живого вызова) - в `mcp-tool-priority.md`, раздел "Экономия контекста". Модель субагента-разведчика подбирать по типу работы (механика - Haiku, интерпретация BSL - Sonnet+): см. «Модель субагента по типу задачи».

### Батчинг операций

Вместо 10 отдельных вопросов — 1 батч. Вместо последовательных агентов — параллельные.

### Переиспользование результатов

Результаты исследования, принятые решения, найденные паттерны — сохранять и переиспользовать, не перечитывать заново.

## Антипаттерны

| Антипаттерн | Правильно |
|-------------|-----------|
| Sonnet/Haiku для оркестратора (основная сессия) | Opus |
| Opus на механической разведке ВНЕ кода (файловые списки, греп по тексту/логам) | Haiku (дешевле, качества хватает) |
| Haiku на любой BSL/1С-разведке (даже механической выгрузке структуры) | Sonnet или Opus (Haiku неточен на коде, портит выжимку оркестратору) |
| Opus/Sonnet для кросс-ревью (жжет Claude-токены) | Внешние модели через подписки (Codex, Grok) |
| Чтение всего модуля целиком при поиске одного метода | Читать конкретный метод |
| Последовательный запуск 5 агентов | Параллельный запуск |
| Продолжение чата при огромном контексте | Новый чат с сохранением ключевых решений |
| Fable 5 для рутины / единичных правок | Opus 4.8 или Sonnet (Fable вдвое дороже, ест квоту) |
| Fable 5 на security-анализе (RLS, права, sensitive data) | Opus 4.8 (прибавка Fable там не действует + риск ложного refusal) |

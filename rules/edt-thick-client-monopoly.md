# Монопольная сессия EDT и пакетный Конфигуратор

Применяется: при любой попытке запустить Конфигуратор (толстый клиент, `1cv8 DESIGNER`) или пакетную
команду 1С против файловой ИБ, с которой работает EDT.

---

## Суть

EDT с открытым проектом и подключенной информационной базой держит постоянную сессию Конфигуратора
(AgentMode) и монопольную блокировку файловой ИБ. Прямой запуск пакетного Конфигуратора
(`1cv8 DESIGNER /F <база> ...`, `/DumpCfg`, `/LoadCfg`, `/UpdateDBCfg` и другие) против той же базы
блокируется и не возвращает управление. Это защита от конкуренции за блокировку конфигурации, а не
отказ Конфигуратора и не зависший сеанс.

## Правило для агента

1. **Не запускать пакетный Конфигуратор и `1cv8` напрямую** (Bash, PowerShell, `.bat`) против ИБ,
   которой управляет EDT.
2. **Операции толстого клиента выполнять только инструментами `ai-edt`**: `update_database`, выгрузка
   `.cf` / `.cfe` (`config_io operation=export_database_configuration` / `export_database_extension`,
   `export_extension`), `list_extension`, `install_extension` / `uninstall_extension`, `export_object`
   (`.epf` / `.erf`), `create_infobase`, `unpack_external_binary`. Они освобождают сессию EDT, запускают
   свой процесс Конфигуратора и восстанавливают подключение, поэтому монополия передается корректно.
   Доводы и отказы - скил `ai-edt-tools`, `references/facades.md` и `references/infobase-debug-tests.md`.

   `import_configuration_from_binary` (`.cf` / `.cfe`) тоже запускает Конфигуратор, но рабочую ИБ не
   трогает: создает временную базу, загружает в нее файл, выгружает XML, импортирует его в новый проект
   и удаляет базу. Блокировка рабочей базы не нужна, операция безопасна при занятом рабочем
   пространстве. На крупной конфигурации она идет минутами и отвечает `Pending` с `runKey`; результат
   забирать по ключу.
3. **Инструмент толстого клиента не возвращает управление или превышает таймаут - это не "Конфигуратор
   сломан".** Причины:
   - внешний клиент 1С (открытые пользователем Предприятие или Конфигуратор) держит файловую ИБ;
   - EDT не освободила сессию (рассинхрон блокировки);
   - операция длительная (крупная выгрузка `.cf` / `.cfe`, реструктуризация).

   Действие: `self_status`, `debug_status`, вопрос пользователю, что показывает EDT. Прямой запуск
   Конфигуратора ситуацию не исправляет, а усугубляет.
4. **Серверная (SQL) ИБ**: файловой блокировки нет, но сессия EDT может конфликтовать за блокировку
   конфигурации. Правило то же: только через инструменты `ai-edt`.

## Сборка .cf / .cfe идет из конфигурации ИБ - сначала update_database

Выгрузка `.cfe` и `.cf` собирает файл из конфигурации подключенной ИБ, а не из исходников EDT-проекта.
Правки проекта (`write_module_source`, `edit_metadata` и другие) в файл не попадают, пока не применены
к конфигурации ИБ.

Порядок:

1. `update_database` - применить изменения проекта к конфигурации ИБ.
2. Выгрузка `.cfe` / `.cf` из обновленной конфигурации.

Без шага 1 выгружается прежняя версия: модуль исправлен в EDT, а в `.cfe` изменений нет.

Закрывать Конфигуратор пользователю перед выгрузкой не нужно. EDT держит соединение с Конфигуратором
как служебное, и инструменты `ai-edt` работают через него (освобождение сессии, свой процесс,
восстановление подключения).

### Проект расширения

Проект расширения, созданный в EDT, в ИБ не регистрируется, и правки модуля туда не попадают сами.
С AI-EDT 0.2.26 `update_database` по проекту расширения обновляет ИБ родительской конфигурации (ответ
несет `infobaseProject`, `viaParentProject`), поэтому маршрут один:

1. `update_database dryRun=true` - смотреть `readiness` и `updateState`.
2. Проверить, что базовый проект не расходится с ИБ: инкремент считается по приложению родителя, и
   расхождение базы уйдет в ИБ вместе с расширением.
3. `update_database`, затем выгрузка `.cfe`.
4. `v8unpack -E` по полученному `.cfe` и сверка модуля с проектом (скил `v8unpack-cf`).

Обход через подмену модуля нужен только при ответе
`No application to update ... neither does the configuration it extends` (приложения нет ни у
расширения, ни у родителя): `v8unpack -E` -> заменить `CommonModule/<Имя>/CommonModule.obj.bsl` ->
`v8unpack -B --version <8XXYY>` -> сверка распаковкой -> `install_extension` -> выгрузка `.cfe`.

Выгрузка `.cfe` расширения из файловой ИБ при конфигурации больше 4 ГБ - скил `ai-edt-tools`,
`references/gotchas-and-errors.md`.

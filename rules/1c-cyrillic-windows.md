# Кириллица в путях и аргументах на Windows

Применяется: когда в пути, имени файла, имени базы или учетных данных есть не-ASCII символы, и когда
автоматизация запускает платформу 1С. В 1С-проектах это норма: русские каталоги, русские имена баз,
русские имена пользователей информационной базы.

Читать до первой команды с кириллическим путем: без этого агент подбирает варианты вызова вместо
диагностики, а часть отказов молчаливая.

---

## Симптомы и их причины

| Что видно | Причина |
|---|---|
| `Пользователь ИБ не идентифицирован`, платформа завершается через секунду после запуска | кириллица в имени пользователя базы потерялась на границе Win32 |
| `РђРґРјРёРЅ` вместо `Админ` в выводе | байты UTF-8 прочитаны как однобайтовая кодировка |
| `1С` превратилось в `1РЎ` внутри скрипта | файл без метки кодировки прочитан как ANSI |
| Файл существует, а инструмент сообщает, что его нет | путь перекодирован по дороге между оболочкой и файловой системой |
| Удаление прошло без ошибки, а файл на месте | молчаливый отказ, см. раздел про удаление |

## Учетные данные с кириллицей

Встречается утверждение, что кириллица в имени пользователя теряется на границе Win32 при запуске платформы
из управляемой среды и лечится только латинским именем. **Проверено частично, и в проверенной части
утверждение не подтвердилось.**

Замер на 8.3.27.1859, запуск из PowerShell: имя пользователя хранилища `Администратор`, переданное
ключом `/ConfigurationRepositoryN`, платформой принято, операция выполнена. То есть для этого ключа
кириллица работает.

Про имя пользователя информационной базы (ключ `/N`) замера у нас нет: подходящей базы под рукой не
было. Пока замера нет, правило такое:

- симптом `Пользователь ИБ не идентифицирован` при запуске с русским именем пользователя - повод
  проверить именно передачу аргумента, а не только пароль и права;
- для конвейеров, где отказ дорог, безопаснее завести пользователя с латинским именем (`agent`,
  `runner`): это снимает вопрос целиком и ничего не стоит;
- утверждать, что кириллица в `/N` не работает, оснований у нас нет.

Конфигурацию и данные это в любом случае не касается: речь только про имя учетной записи.

## Выбор инструмента для операций с путями

- Пути с не-ASCII обрабатываются средствами, работающими с Unicode напрямую: файловые операции самого
  агента, PowerShell, python с явной кодировкой.
- Кириллица не передается аргументом командной строки через оболочки, которые перекодируют аргументы.
  Если инструмент дважды подряд не нашел существующий файл - проблема в передаче пути, а не в файле, и
  третья попытка тем же способом не поможет.
- В python путь с кириллицей лучше держать внутри скрипта, а не получать аргументом, и первой строкой
  переключать поток вывода на UTF-8.

## Файлы скриптов

- **Скрипт PowerShell с кириллицей внутри сохраняется с меткой кодировки UTF-8.** Без нее интерпретатор
  прошлого поколения читает файл как ANSI и портит все русские строки. Инструменты записи файлов такую
  метку обычно не ставят - ее добавляют отдельно после создания.
- **Пакетные файлы для запуска платформы пишутся в однобайтовой кодировке**, а не в UTF-8. Такой файл
  готовится преобразованием из UTF-8-исходника, а не набирается напрямую.

## Долгая работа в кириллическом каталоге

Когда операций много, проще один раз создать переход на латинский путь и работать через него: файлы
остаются на месте, а все инструменты видят путь без не-ASCII.

Предлагать пользователю переименовать его каталоги не надо: кириллица в пути - его выбор, а переход
менее навязчив и обратим.

## Молчаливый отказ при удалении

Замер на Node v24.11.1: рекурсивное удаление штатным средством НЕ удаляет путь, в котором есть
кириллица, - ни исключения, ни удаления, и это верно даже для пустого каталога. Тем же поражен вариант
рекурсивного удаления каталога. Удаление одного файла и удаление пустого каталога без рекурсии работают.

Практическое следствие: инструмент, снимающий блокировку удалением файла-маркера, отчитывается об
успехе, а маркер остается навсегда. Временные каталоги копятся, эталоны не перезаписываются, и в выводе
ни одной ошибки.

Общее правило шире одного дефекта: **успех удаления подтверждается отсутствием пути, а не тем, что
вызов не бросил исключение.** В этом наборе обход собран в `tests/skills/fs-safe.mjs`.

## Дисциплина

1. Кириллицу из содержимого файлов не убирать: русский текст в 1С-проектах это норма.
2. Каталоги пользователя не переименовывать и не предлагать этого без нужды.
3. Инструмент дважды споткнулся на кодировке - сменить инструмент, а не повторять третий раз.

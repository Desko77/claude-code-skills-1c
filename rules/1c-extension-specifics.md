# Особенности расширений 1С и выгрузки внешних обработок

Применяется: при разработке расширений конфигурации (CFE) - перехваты, заимствование, подписки,
перенос доработок между релизами типовой - и при сравнении XML-выгрузок внешних обработок.

Типы перехватчиков, `ПродолжитьВызов()` и маркеры изменений - `1c-extension-patterns.md`. Заимствование
и смена типов заимствованного объекта инструментами плагина - скил `ai-edt-tools`,
`references/gotchas-and-errors.md`. Сборка `.cfe` - `edt-thick-client-monopoly.md`.

---

## Перехваты

- **`&Вместо` не видит неэкспортные функции типового модуля** ("функция не определена"): копировать
  функцию в расширение (с вызовами только экспортных методов) или использовать `&ИзменениеИКонтроль`.
- **Тело в `&ИзменениеИКонтроль` должно совпадать с типовым методом вне блоков `#Вставка` /
  `#Удаление`.** Разный отступ (3 и 4 табуляции) внутри `#Вставка` ломает компиляцию всего модуля.
- **Патч-расширение с копией недавно измененной типовой функции** может вызывать экспортные методы,
  которых нет в рабочей базе, - такие вызовы убирать. `git apply` частичного патча поверх
  параллельных правок дает дубли методов: после применения проверять
  `grep "^Функция" | sort | uniq -d`.

## Заимствование

- **Реквизит расширения со ссылочным типом основной конфигурации - заимствовать объект этого типа**,
  иначе MINOR "Неизвестный тип" и неявная зависимость. Объекты самого расширения заимствовать не нужно.
- **Один объект - одно расширение**: повторное заимствование в другом расширении конфликтует по
  перехватам.
- **Связка заимствованного `.mdo` с типовым объектом** (`extendedConfigurationObject`,
  `<module>Extended</module>`): без нее модуль расширения не расширяет типовой при нулевых ошибках
  проекта. Как связку пишет плагин и как исправить объект, заимствованный прежней сборкой, - скил
  `ai-edt-tools`, `references/gotchas-and-errors.md`, раздел "Заимствованный объект". UUID для
  сверки - из `.mdo` типового объекта базового проекта.
- **Подписка на событие в расширении с `<source>DocumentObject.X</source>`** - инкрементальная
  загрузка отказывает "Неизвестное имя типа". Исправление - полная загрузка или заимствование
  документа.
- **Заимствованные модули физически не удалять** (останется файл без объекта) - заменять тело
  заглушкой, `.mdo` оставлять. При удалении объекта: сначала `Configuration.mdo`, затем каталоги.

## Перенос доработок при обновлении типовой

- **Версионная форма**: существующую форму не править, а создать копию эталона с именем версии
  (`ФормаДокумента_3_1_34_XXX`, идентификаторы эталона) и переключить `defaultObjectForm`. Собственный
  UUID версионной формы ошибкой не является.
- **Конфигурации сторонних поставщиков дорабатывать только расширениями**, перед обновлением версии
  поставщика - регрессионные тесты YAxUnit.

## XML-выгрузка внешней обработки

- **Выгрузка `.epf` в XML на платформе 8.3.27.2214 пишет значение заполнения ссылочных реквизитов как
  `<FillValue xsi:nil="true"/>`**, а в XML, выгруженном более ранней версией платформы, у тех же
  реквизитов стоит `<FillValue xsi:type="xs:string"/>`. В сравнении это выглядит как массовая правка
  свойств при неизмененных метаданных; выгрузка исходного `.epf` до правки дает тот же `nil`.
  Строковые реквизиты остаются `xs:string`. На поведение не влияет: незаданное значение заполнения
  ссылочного реквизита - пустая ссылка.
- В XML, выгруженном без конфигурации, ссылочные типы бывают записаны как `xs:string` длины 10 -
  собирать `.epf` из такого XML нельзя, типы станут строками.

# Спецификация каталога дефектов 1С

Каталог дефектов - данные, а не проза: каждый дефект описан карточкой с фиксированным набором
полей, имеет идентификатор из реестра и фикстуру. Индекс и каталожные секции правил
генерируются из карточек скриптом `tools/gen_catalog_index.py`.

Расположение: `skills/1c-code-review/references/catalog/`.

## Идентификаторы

Формат: `<группа>-<номер>`, номер двузначный, сквозной внутри группы (`PERF-01`, `PERF-02`).

Группы:

| Префикс | Смысл |
|---------|-------|
| `MODEL-` | признаки кода, написанного моделью |
| `PERF-` | производительность |
| `QUERY-` | язык запросов |
| `TXN-` | транзакции и блокировки |
| `FORM-` | управляемые формы |
| `CLIENT-` | клиент-серверное взаимодействие |
| `SEC-` | безопасность |
| `EXT-` | расширения конфигурации |
| `META-` | метаданные |
| `PROC-` | дефекты процесса ответа ("проверено" без следа) |

Идентификатор выдается записью в реестре `catalog/ledger.json` и после вывода из каталога не
переиспользуется. Формат реестра:

```json
{
  "issued": [
    {"id": "PERF-01", "date": "2026-09-21", "title": "Запрос в цикле"}
  ],
  "retired": [
    {"id": "XXX-99", "date": "2026-01-01", "reason": "поглощен карточкой YYY-01"}
  ]
}
```

## Формат карточки

Карточка - файл `<ИДЕНТИФИКАТОР>.md`. Заголовок первого уровня: `# <ИДЕНТИФИКАТОР>. <Заголовок>`.
Разделы второго уровня присутствуют все и строго в этом порядке:

| # | Раздел | Содержимое |
|---|--------|-----------|
| 1 | `## Идентификатор и группа` | строки `Идентификатор:` и `Группа:`; для перенесенных из `anti_patterns.md` - строка `Псевдоним: п.N` |
| 2 | `## Важность` | один из уровней: Critical, Major, Minor (шкала - `severity.md`) |
| 3 | `## Триггер` | что видно в коде или diff; первая строка раздела - формулировка одной строкой для индекса |
| 4 | `## Почему дефект` | последствия |
| 5 | `## Законная форма` | код, где признак триггера присутствует, а дефекта нет. Обязательна |
| 6 | `## Как чинить` | способ исправления |
| 7 | `## Детекторы` | таблица сред: EDT, Конфигуратор |
| 8 | `## Архетипы правки` | подмножество списка архетипов через запятую |
| 9 | `## Фикстура` | строки `Тип:` (bsl-pair, project-tree, diff, evidence) и `Путь:` |
| 10 | `## Источник` | номер стандарта `#stdNNN` (только если известен точно), либо `правило <файл> <пункт>, перенесено <дата>`, либо инцидент с датой |

Архетипы правки (полный список): транзакция, блокировка, права, запрос, модуль формы,
событие объекта, новый общий модуль, перехват в расширении, изменение метаданных, любой BSL.

Законная форма, отсутствовавшая в исходном правиле, помечается в разделе строкой
`законная форма добавлена <дата>`.

## Фикстуры

Каталог фикстур: `tests/catalog/<ИДЕНТИФИКАТОР>/`. Манифест `manifest.json` задает тип и
ожидания; файлы фикстуры лежат рядом с манифестом.

| Тип | Файлы | Манифест |
|-----|-------|----------|
| `bsl-pair` | `clean.bsl`, `defect.bsl` | `"type": "bsl-pair"`, `"expected": [номера строк срабатывания в defect.bsl]` |
| `project-tree` | файлы выгрузки (`.mdo`, `.form`, XML) | `"type": "project-tree"`, `"files": [список путей относительно каталога фикстуры]` |
| `diff` | `before.bsl`, `after.bsl` | `"type": "diff"`, `"expected": [номера строк в after.bsl]` |
| `evidence` | файл следа проверок | `"type": "evidence"`, структурная проверка манифеста |

Модули фикстур - кириллический BSL, 10-30 строк, кодировка UTF-8.

## Генерация

`tools/gen_catalog_index.py` читает карточки, проверяет обязательные поля и пишет:

- `catalog/INDEX.md` - таблица: идентификатор, важность, группа, архетипы, детекторы, триггер
  одной строкой; сортировка по идентификатору;
- секции между маркерами `<!-- catalog:begin -->` и `<!-- catalog:end -->` в
  `rules/anti_patterns.md` (таблица триггеров с колонкой псевдонима "п.N") и
  `rules/code-review-checklist.md` (таблица по группам с важностью).

Вне маркеров файлы правил скрипт не меняет. Режим `--check` выходит с кодом 1, если
сгенерированное отличается от файлов на диске. Одинаковый вход дает байт в байт одинаковый выход.

## Как добавить карточку

1. Выдать идентификатор записью в `ledger.json` (проверить, что номер группы свободен).
2. Написать карточку по формату, с законной формой.
3. Создать фикстуру `tests/catalog/<ИДЕНТИФИКАТОР>/`.
4. Выполнить `python tools/gen_catalog_index.py` - индекс и секции правил обновятся.
5. Прогнать `node tests/skills/check-all.mjs` - гард `check-catalog.mjs` сверяет карточки,
   реестр, фикстуры и совпадение сгенерированного.
